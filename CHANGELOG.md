# Changelog

All notable AIDraw changes are recorded here. The project follows Semantic Versioning; prerelease versions remain explicitly pre-v1 until every release gate in the feature tracker is satisfied.

## [Unreleased]

- Continue the audited v1 critical path in `docs/FEATURE_TRACKER.md`.
- Correct square-tile Tiled transformation rendering. Diagonal now means the Tiled anti-diagonal transform and is applied before horizontal and vertical flags through one shared core matrix used by both the live canvas and headless/export renderer; the former duplicated Canvas composition swapped diagonal-only with diagonal-plus-both-flips. Exact labeled-pixel coverage, a maintained raw-RGBA golden, and a separate production TMJ+PNG round trip prove all eight unsigned GID combinations. Transform thumbnails, packaged interaction, isometric-specific visual evidence, non-square tile policy, and broad Tiled fidelity remain outside this checkpoint.
- Close the adjacent embedded-image gap at utility-import and profile-recovery ingress. Every utility-imported document now passes its complete generic-asset metadata through the main-owned migration/envelope gate; each embedded payload must then satisfy the established canonical base64, length/SHA, PNG/APNG/JPEG/WebP/GIF MIME/header, 128 MiB, display-geometry, 8,192-side, and 16MP checks and complete a supervised codec decode before the import can resolve. A malformed envelope retires its producer, and decoder-process exit returns no document. Profile recovery applies the same payload checks before recovered bytes become canonical: invalid bytes are omitted while the document, dirty/file/tab state, and asset metadata remain available, and an attached editor receives one aggregate startup warning. Whole-import rejection was retained because a worker result is not yet user state; metadata-preserving omission was chosen for recovery because rejecting the document would discard otherwise recoverable unsaved work. Silent recovery was rejected because missing artwork must remain visible to the user. Metadata-only recovery records, exact packaged warning presentation, arbitrary codecs, and broad PDF/PSD/image compatibility remain outside this checkpoint.
- Contain generic raster admission behind the existing supervised utility lane instead of invoking the native canvas decoder on arbitrary bytes in the main process. Live `asset.add`, production native open/save, and packaged CLI native reads first enforce canonical base64, declared length, SHA-256, PNG/APNG/JPEG/WebP/GIF MIME/header agreement, display geometry, the existing 8,192-side/16MP limit, and their established 1.5 MB inline or 128 MiB native-entry byte ceiling; only then does a typed `validate-image` request perform the real codec decode in the worker. A decoder-process exit rejects the active request and queued work resumes in a fresh worker. Live admission rejects without mutation; native open and CLI retain metadata but omit invalid data with an explicit warning; save rejects before preview rendering, temporary creation, or destination replacement. Warning-and-omission was retained over whole-document rejection to preserve the established partial-recovery contract, while the unsafe in-process-decoder alternative was rejected because malformed header-valid input can terminate its host process. This is source-level crash containment for those ingress paths, not recovery-journal or utility-import-result asset reconciliation, arbitrary codec compatibility, packaged/native acceptance, Level 3, or RC evidence.
- Reject canonical pixel palette references that cannot name an authored color. Persisted native, recovery, and utility-imported sprites and reusable stamps now require every indexed value to be below the current palette length; live cel/region, frame, asset, and stamp ingress enforces the same rule at its sequential reducer position. Per-frame palette overrides must exactly match the current palette length and entry-ID order, while their colors may differ; deleting a frame removes its override and undo restores the prior sprite. Rejection was chosen over silently remapping to transparent or the renderer's magenta missing-color diagnostic because either changes authored color meaning. Missing linked/group/asset/cache targets retain their established recovery behavior. This is exact indexed-color integrity, not general graph reconciliation, packaged/UI, Level 3, or RC evidence.
- Validate the normalized canonical state of pixel documents before native, recovery, or utility-imported content reaches rendering/export. It does not authenticate linked content, claim arbitrary repair, packaged behavior, Level 3, or RC evidence.
