# Security policy

## Supported version

AIDraw is currently pre-v1. Security fixes target the latest published prerelease. Windows 11 x64 remains the release-evidence baseline; Apple Silicon has an exact-artifact independent Level 2 native interaction PASS, while macOS and Linux remain prerelease targets until hosted native, signing/clean-machine, and Level 3 security gates pass. Once v1 ships, the latest stable release becomes the supported line.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting for the `aidraw` repository, or contact the repository owner through the private address listed in the GitHub security advisory form. Include the affected version, impact, reproduction, and whether local authority or files may be exposed. You should receive an acknowledgement within three business days.

## Security model

- Renderer processes are sandboxed, context-isolated, denied permissions, and limited to a typed preload API.
- MCP binds only to `127.0.0.1`, requires a random 32-byte bearer minted for one `EngineRuntime`, validates localhost host/origin, caps bodies, and uses stateful sessions. MCP, health, and engine-identity routes all require that bearer; stopping the process invalidates it and every session.
- AIDraw does not use Keychain, DPAPI, libsecret, Electron `safeStorage`, another protected-secret backend, or a durable client bearer. Activity displays a one-time no-secret stdio snippet pointing to a stable product-owned per-profile wrapper and never edits a third-party client configuration. Ordinary GUI and supported headless startup atomically refresh that wrapper to the current installed/relocated executable; the wrapper contains no bearer or per-launch authority. While an engine is live, product-owned private atomic run state carries its PID, random instance identity, loopback URL, and ephemeral bearer solely for that UI-invisible bridge. POSIX requires a plain mode-`0700` root and private files. On Windows, the complete lexical path is checked before and after ACL application and any reparse/non-directory component is rejected. The leaf has a protected current-user-owned DACL with exactly current-user and SYSTEM non-inherited Allow ACEs, exact Full Control, object/container inheritance, and no exceptional propagation so child run-state files inherit the boundary; the same validation applies below caller-selected profiles. The bridge additionally requires double-checked instance/PID state, PID liveness, and a matching authenticated identity; stale or ambiguous reads fail closed. Normal stop removes the instance file after authority invalidation, and any crash-left value is useless after its engine exits or restarts. The explicit `--write-mcp-connection=<absolute-path>` QA/automation option separately writes a caller-owned private plaintext version-two handoff; production neither removes nor redacts it, so its caller must keep it private and remove it. The maintained QA coordinator redacts only its own declared handoff after confirmed stop.
- The stdio bridge serializes ordinary external messages and automatically retries only a response that proves the engine did not process the request (currently stale/missing authority/session or not-ready rejection). Cancellation bypasses that FIFO, reaches the exact active generation without retry, suppresses accepted-but-undispatched work, and blocks a later proven-nondelivery retry; it never reclassifies an ambiguous request as safe. If dispatch may have committed but the response cannot be read or validated, the bridge returns a non-retryable ambiguous-outcome error telling the client to observe canonical state and never resends the request. A successful externally emitted initialize and receipt of initialized intent are separate prerequisites, so failed handshakes cannot advance and every replacement re-establishes ambiguous initialized intent. Known-session DELETE failures remain queued and are retried instead of being forgotten. Every bridge initialize carries a random non-authority provisional ID used only on the authenticated loopback exchange; the host reserves one owner atomically before asynchronous construction, an idempotent authenticated DELETE can retire the matching session without knowing its returned session ID, and every admitted unconfirmed provisional session is forcibly retired server-side within five seconds even if cleanup is lost. A replacement engine receives a fresh internal session and only successful remembered `session_manage join` arguments and resource subscriptions are restored before forwarding the next client request. Unexpected lifetime-stream EOF, reader failure, or malformed/oversized event schedules one serialized generation-checked replacement after any dispatched external request settles; stability admission plus bounded attempts/window prevent a reconnect storm. It replays only bridge-owned initialize/restore messages, never the external request. Persistent and launch-time folder authority are independently re-established by the engine; process-lifetime `allow-session` approval never becomes durable storage.
- A confirmed first-party bridge session is exposed to the stdio client only after an authenticated correlation-bound SSE lifetime stream is established. The host retires that session when the stream closes, making bridge-process exit a server-observed capacity-release boundary even if every explicit session DELETE fails. On Windows, the production boundary requires a ready fixed drive plus an exactly equal canonical volume identity before and after ACL work, rejects mapped/substituted/non-volume aliases, and evaluates every existing ancestor's owner and applicable ACL rights for branch deletion/replacement authority; immediate-parent creation rights are also restricted without rejecting ordinary safe higher user-profile ancestry.
- Deliberate stdin EOF/close, transport error, SIGINT/SIGTERM, or explicit close aborts undispatched work and every replacement phase. Dispatched or ambiguous work is not replayed. Terminal response, body, output-drain, and cleanup waits are bounded; aborting the correlated lifetime and the host's provisional TTL remain the final server-owned retirement paths if a local promise ignores cancellation.
- AIDraw has no native generative-content provider, provider credential, or provider-network workflow. Historical provider/provenance fields in an existing `.aidraw` document are passive compatibility data and cannot be added or removed through renderer or MCP transactions.
- Agent file tools accept exact paths only. They cannot list or delete files; approvals cover untrusted access and all overwrites.
- Exact paths are canonicalized through existing ancestors so junctions/symlinks cannot disguise a target. Session and persistent folder trust never covers an overwrite, including export companion files.
- Committed entity attribution and timestamps are server-owned. Renderer submissions are always human-authored and MCP submissions use the authenticated session actor.
- Inline MCP assets are data-only raster images (PNG/APNG/JPEG/WebP/GIF). AIDraw checks canonical base64, decoded length, SHA-256, MIME/header agreement, actual decode, an 8192 px side limit, and a 16 MP pixel limit; SVG and other active/dangerous inline formats are rejected.

Local malware running as the same OS user, a modified product bridge, caller-owned connection handoffs left on disk, and files deliberately exported to other applications are outside the trust boundary. Treat imported documents and third-party MCP clients as untrusted. The ordinary client configuration never needs access to an engine bearer; copying a transient run-state or explicit-handoff bearer into another program defeats the supported boundary.
