# AIDraw MCP contract

The supported client connection is one static no-secret stdio entry pointing to a product-owned per-profile launcher wrapper. Client configuration contains no installed-version path, URL, bearer, password, account credential, or per-launch value. Every ordinary GUI or supported headless AIDraw launch atomically refreshes that wrapper to the current installed/relocated executable; the wrapper then starts `--mcp-bridge` with inherited stdio. Internally, the UI-invisible bridge resolves the current stateful Streamable HTTP engine at `http://127.0.0.1:<port>/mcp`, supplies the engine bearer, retains the negotiated `Mcp-Session-Id` and protocol version, and transparently reinitializes when the engine instance changes. Direct HTTP, `/health`, and `/mcp/identity` all require the current bearer; AIDraw exposes no unauthenticated control or health endpoint.

`<AIDraw executable> --headless` starts the engine without a renderer. Closing the editor does not terminate sessions or documents. Animated transactions commit immediately while no editor is attached and retain their original operations for later trace replay. Launching AIDraw normally attaches the UI to the same process.

AIDraw retains at most 32 authenticated MCP transport sessions, including capacity reserved by initializations in progress. A simultaneous 33rd initializer receives HTTP 429 with `session_limit_reached`; retry after terminating an unused session with an authenticated HTTP DELETE carrying that session's `Mcp-Session-Id`. Deleting a transport session removes its presence, resource subscriptions, and session-scoped folder trust. `session_manage` with `action: "leave"` removes presence only and deliberately does not terminate the transport. Established sessions are not silently idle-evicted. A first-party bridge initialize is provisional until the bridge confirms it through the matching session/correlation headers. Correlation ownership is reserved synchronously before asynchronous session construction, so concurrent duplicate IDs cannot displace an owner's retirement timer. Every admitted unconfirmed provisional session is retired after five seconds, and full engine shutdown closes every session.

Confirmation is granted only by the first matching authenticated request, which is the bridge's SSE lifetime stream. The initialize result is not returned to the stdio client until that stream exists. Its disconnect retires the confirmed host session, presence, subscriptions, and session folder trust even if all explicit DELETE attempts fail, preventing a dead bridge process from consuming one of the 32 slots. If the stdio bridge itself remains alive, unexpected EOF, reader failure, or malformed/oversized event data schedules one serialized generation-checked replacement and remembered-state restoration without waiting for another client request. A replacement is admitted only after its stream remains stable; immediate failures receive bounded attempts and a cross-generation window limit. This process-lifetime boundary is specific to correlated first-party bridge sessions; ordinary direct sessions retain explicit DELETE/engine-stop lifetime.

Each GUI or supported headless engine launch publishes product-owned live discovery state under its user-data `runtime` directory. A non-secret pointer names one random engine instance and PID; a separate mode-`0600` instance file contains that engine's loopback URL and fresh bearer. Both are complete atomic replacements inside a plain mode-`0700` directory on POSIX. On Windows, AIDraw walks the complete lexical path to the volume root before and after ACL application and rejects every reparse/non-directory component. The leaf DACL is protected and current-user-owned and contains exactly current-user and SYSTEM non-inherited Allow ACEs, each exact Full Control with object/container inheritance and no exceptional propagation so child files inherit the same restriction. The rule also applies below an explicitly selected profile and is revalidated before discovery. The bridge double-reads the pointer around the instance file, requires a live PID, and authenticates `/mcp/identity` before using it. Corrupt, permissive, stale, changing, or mismatched state grants nothing. Orderly stop invalidates the host before removing that unguessable instance file. A harmless stale pointer is deliberately retained so an old process cannot delete a successor's pointer; a restart replaces it atomically. Crash-left authority is useless after its process exits and cannot authenticate a later engine.

Windows path syntax is only preflight. The production PowerShell boundary requires a ready `Fixed` drive and canonical volume-GUID identity before and after ACL work, and the two exact identities must match, so mapped network drives, substituted aliases, volume switching, UNC/device roots, and non-volume aliases fail closed. It inspects each existing ancestor's owner and applicable ACL rules: owners are limited to the current user, SYSTEM, Administrators, or TrustedInstaller; unrelated-principal Allow rules may not grant delete, delete-child, change-permission, or take-ownership authority anywhere in the branch, and may not grant create-file/create-directory authority on the immediate parent. Safe read/traverse rights and ordinary higher-level sibling creation remain compatible with normal Windows user-profile ancestry.

For explicit QA or automation provisioning, a launcher may additionally use `--write-mcp-connection=<absolute-json-path>`. An empty or relative value is rejected. Once the server starts, AIDraw publishes a version-two private handoff with its URL, token, active document ID, process ID, launch-time trusted folders, and `authority: "engine-process"`. The complete JSON is written through a private flushed atomic replacement and is valid only while that PID owns the engine. This opt-in caller-owned file is not the ordinary client connection path or product credential storage. Production does not remove or redact a requested handoff. Restrict it to the current OS user and remove it after the consuming automation has connected. The maintained QA coordinator separately redacts only its own declared handoff after it confirms that engine has stopped.

## Discovery and cold start

The initialize result carries compact cross-tool instructions, but clients are not required to display them. Correct use therefore remains learnable from the reliable exact ordered nine-tool `tools/list` plus `tools/call` surface: call `aidraw_help` with `topic: "quickstart"`, join or inspect the session, list documents, observe canonical state, and only then apply a revision-aware transaction. `aidraw_help` is progressive (`quickstart`, `documents`, `canvas`, `jobs`, `history`, `files`, `operations`, or `safety`) and returns structured content plus safe examples and the optional guide URI. A direct HTTP client must call `session_manage` with `action: "join"` for each new transport if it wants stable presence and transaction attribution; a descriptive initialize name is not a durable actor identity. The supported product bridge instead remembers only a successful join's exact name/color/document/model/reasoning/task arguments and restores them on its replacement internal transport without external client action.

The endpoint currently uses the installed SDK's stateful legacy initialize/session profile and negotiates `2025-11-25`. A legacy initialize that supplies an unsupported or modern-only version receives `2025-11-25` in the initialize result; every later request must send that negotiated value in `MCP-Protocol-Version`, and an unsupported value is rejected with HTTP 400. A transport session ID exists only for the lifetime of the owning AIDraw process. After HTTP 404 `unknown_session`, discard the stale ID, initialize a fresh transport, and join again. AIDraw does not currently advertise the distinct modern `server/discover` profile.

The `session_manage`, `document_manage`, `history_manage`, and `job_manage` discovery schemas use one flat object apiece: `action` is a required enum and every branch field is optional, action-labelled, and composition-free (`oneOf`/`anyOf`/`allOf` are absent). This compatibility projection is discovery-only. The server still strictly requires fields such as `path` for `open`, `documentId` plus `path` for `save-as`, `checkpointId` plus `sourceIds` for `checkpoint-merge`, and `jobId` for `wait`, and it rejects fields belonging to another action. Important observation, idempotency, revision, file, batch, and output fields retain protocol-visible descriptions.

Incomplete approval or running jobs return a safe `next` call for owner-scoped `job_manage`; waiting results explicitly state that only a human can approve in AIDraw. Retryable canvas conflicts, locks, busy queues, and cancellation point back to canonical observation. These hints never disclose raw job results, paths, approval internals, tokens, or other private data. Clients that support resources may read the complete progressive reference at `aidraw://guide`; clients that ignore instructions and resources retain the same correctness baseline through tools and results alone.

## Agent clients

Activity offers one-time stdio configuration profiles for Codex, Claude Code, OpenCode, Antigravity, and a generic MCP client. Selecting **Show setup** returns `/bin/sh` plus the stable per-profile wrapper on macOS/Linux, or system `cmd.exe` plus the stable `.cmd` wrapper on Windows. The generated strings reject every U+0000–U+001F and U+007F control before JSON/TOML escaping. AIDraw does not inspect, back up, or edit client configuration, and it does not change start-at-login state. Add the profile once to a client you trust. If that client starts before AIDraw, the bridge waits up to 30 seconds for a valid current engine; a timeout produces a retryable JSON-RPC error and the same configured client can try again after the user launches AIDraw. Ordinary AIDraw launch refreshes the wrapper first, so macOS/Linux relocation and Squirrel version changes do not require a client edit. Current local Apple Silicon installed-headless acceptance proves this behavior with a generic command-line client through relocation, graceful restart, and process death; the per-vendor profile shapes remain formatting guidance rather than evidence for those vendors' installed UI behavior.

### Ephemeral authority lifetime

Each `EngineRuntime.start()` mints a fresh random 32-byte bearer. There is no durable client bearer, revoke marker, rotation workflow, protected-secret backend, or account. The supported bridge reads that bearer from the private product-owned engine run file; it is never included in generated client configuration. The separately authorized direct QA/automation surfaces remain those described above. Stopping the engine closes transports, invalidates that bearer, and removes its instance file; the next process receives an unrelated bearer and instance identity. The long-lived stdio bridge detects a new identity or unexpected lifetime-stream interruption, initializes a new internal session, sends the initialized boundary, then restores successful joined attribution/document intent and exact resource subscriptions before another client message is needed. It tracks a successfully emitted external initialize result separately from receipt of initialized intent: failed initialize cannot authorize later traffic, while ambiguous delivery of the first initialized notification still causes every replacement to re-establish that boundary before dispatch. Direct stale bearer/session use still fails with 401/404. Committed documents, traces, histories, persistent folder approvals, repeated launch-time trust, and the client's one-time launcher configuration are independent of transport lifetime. A human's `allow-session` choice remains process/session-lifetime authority and is intentionally not converted into durable bridge configuration.

The bridge serializes ordinary requests and does not use a generic replay policy. `notifications/cancelled` bypasses that FIFO: it is sent without retry to the exact generation processing an active request, while an accepted but undispatched target is suppressed with JSON-RPC `-32800`. Cancellation never converts an ambiguous outcome into a retry. A 401, 404, or not-ready 503 response proves that the target did not process the request and may trigger one fresh internal-session retry unless cancellation has arrived. Once dispatch may have reached the engine, a transport failure, unreadable/invalid response, missing matching result, or uncertain HTTP status returns JSON-RPC error `-32002` with `ambiguousOutcome: true` and `retryable: false`; the request is never replayed. Known-session retirement stays in a recoverable queue until authenticated DELETE succeeds or the host proves it stale, and transient DELETE failures are retried. Before every initialize dispatch, the bridge generates a random non-authority provisional correlation ID. If the complete response disappears before `Mcp-Session-Id` is usable, the bridge can issue authenticated idempotent cleanup by that ID; a bounded host tombstone closes the request/cleanup race, and any still-unconfirmed provisional session expires after five seconds. Observe canonical state before forming a new logical operation. Initialization itself does not mutate artwork, so its failure remains retryable after this bounded retirement path.

Deliberate stdin EOF/close, stdio transport failure, SIGINT/SIGTERM, or explicit bridge close synchronously cancels every accepted but undispatched request and each discovery, initialization, lifetime-admission, initialized, and restoration continuation. Already-dispatched or ambiguously dispatched work is never resent. Engine response, response-body, output-drain, and cleanup waits cannot hold terminal shutdown indefinitely; the bridge stops waiting at a fixed deadline, aborts its correlated lifetime, and leaves host-observed stream retirement plus bounded provisional TTL as the final capacity boundary.

After the bridge learns a confirmed session ID, explicit DELETE remains best-effort and recoverable but is not the sole process-exit cleanup path: aborting or losing the authenticated correlated SSE lifetime stream retires the session at the host. The bridge still attempts DELETE so a live process can confirm cleanup immediately; persistent DELETE failure is reported without leaving host capacity occupied after stdio exit. Unexpected EOF/error while stdio remains open starts at most one generation-owned recovery, waits for any in-flight external request to settle, and replays only bridge-owned initialization/restoration messages.

### Troubleshooting the stateful endpoint

- **Bridge says engine not ready:** launch AIDraw normally or with `--headless`, then let the configured client retry. Do not add a token or rewrite the client configuration.
- **Direct HTTP 401 Unauthorized:** the bearer is absent, wrong, or belongs to another/stopped engine process. Ordinary clients should use the stdio bridge. Explicit QA callers must obtain a fresh caller-owned handoff, initialize a new transport, and never retry an old copied bearer.
- **400 Bad Request:** inspect initialization shape and `MCP-Protocol-Version`; after initialize, send the exact negotiated `2025-11-25` value.
- **404 `unknown_session`:** the process-lifetime session is stale. Discard its ID, initialize without it, then call `session_manage` `join` again.
- **Bridge error `-32002`:** the engine may have committed the request but the bridge could not validate its response. Do not resend it. Observe the addressed document/job/history first and use a new logical request only if canonical state proves it is still needed.
- **Tool result `Invalid arguments`:** transport/auth/session succeeded, but the selected action's strict required/forbidden field contract failed. Re-read that tool's flat schema and action-labelled descriptions.

The direct 401, initialization-required 400, unsupported-version 400, and unknown-session 404 paths return no-store JSON with `profile: "stateful-legacy"`, `protocolVersion: "2025-11-25"`, a stable error code, a neutral message, and a safe `next` action. The 401 response never confirms whether a particular bearer exists or remains valid. Tool validation errors stay inside the authenticated MCP result because reaching them already proves transport, authentication, and session routing succeeded. This wire/help contract is source-level configuration-profile support, not evidence that an installed client displays or follows the guidance.

The same launcher may repeat `--trust-folder=<absolute-folder-path>` to grant process-lifetime file authority to the headless MCP sessions it starts. AIDraw accepts this flag only when both `--headless` and `--write-mcp-connection` are present, realpath-canonicalizes the grants (including macOS `/var` → `/private/var` aliases), reports them in the connection JSON, and does not persist them. Trusted sessions can read existing addressed import sources and create new save/export files within those folders without attaching an editor. Existing save/export destinations are always treated as overwrites and still create approval jobs. Canonicalization prevents a symlink inside a trusted folder from granting authority to its outside target.

## Tools

- `aidraw_help`: model-callable progressive workflow guidance available to tools-only clients; its structured output names related tools, invariants, safe examples, and the optional guide resource.
- `session_manage`: join/name/color, optionally declare client model/reasoning-effort/task metadata, inspect presence plus human occupancy/advisory editor state, or leave. Advisory state may include the attached editor's tool, selection, zoom, visible world viewport, and active pixel asset/frame/tag/onion-skin/playback direction. Client metadata is descriptive and is not platform-attested.
- `canvas_observe`: structured snapshot or diffs, optionally with a targeted base64 PNG. PNG requests may select current or named-checkpoint state, pixel asset/frame/layer or illustration layer, crop to a region, evaluate a schema-2 illustration at exact `illustrationTimeMs`, scale 1–16× with nearest-neighbor output, and choose document, transparent, or explicit solid background. `compareTransactionId` returns a race-free before/after pair for the most recent committed transaction; `checkpointId` observes a persistent editable branch point. Tilemap PNGs render only the requested nonnegative region inside the nominal projected map rectangle rather than first allocating the whole map. Requests return `observation_too_large` before rendering above the 4,194,304-pixel budget (split evenly for a pair), `observation_dimensions_too_large` above 65,535 pixels on either output side, and `observation_png_too_large` after an encoded PNG exceeds 4 MiB. These are raster-allocation limits, not an infinite-map origin or stored-chunk-bounds promise. Its `fragment` selector exports a self-contained editable illustration-object or pixel-asset graph without touching the OS clipboard.
- `canvas_apply`: up to 256 application-owned operations with an idempotent `clientOperationId`, expected revisions, and instant or visible playback. It also accepts `document.fragment.import`; the 2 MiB fragment is validated, IDs and dependency references are remapped, pixel colors are reconciled with the destination palette, and entity attribution is rewritten to the authenticated session.
- `history_manage`: undo/redo only the calling MCP actor, start a bounded non-mutating trace replay by transaction ID, or create/list/restore/delete attributed named checkpoints. `checkpoint-merge` selectively copies named top-level layer trees or pixel assets with dependency closure into the current document as one undoable transaction. Restoring preserves the branch being left as an automatic checkpoint; agents may delete only checkpoints they created.
- `document_manage`: list/new/activate/open/save/save-as/close. `list` returns `activeDocumentId`; `new` shares the strict human contract for kind, name, dimensions, illustration background, map orientation, finite/infinite mode, and tile geometry.
- `asset_import`: import one explicit path after applicable approval. It can open ordinary artwork, slice PNG/JPEG/WebP sheets with exact frame size/margins/spacing/order/count/duration plus optional shared trim and empty-cell skipping, import JSON/GPL palettes into a named pixel document, or set `projectLinkId` to relink an existing saved pixel-project source. Settings and the target link appear in the same human approval as the path. Metadata/Tiled companion references must be relative and remain within the approved root folder after realpath resolution; imports are byte- and expansion-bounded in the utility process.
- `document_export`: export one explicit path; filename extension is required. Its optional `scale` is an integer from 1 to 64 and applies nearest-neighbor presentation scaling to pixel PNG/JPEG/WebP/SVG/PDF/GIF/APNG/sprite-sheet exports. Pixel GIF, APNG, and sprite-sheet requests may provide one exact `animationTagId` to follow only that independent tag's forward, reverse, or ping-pong sequence; missing IDs and incompatible formats fail before approval, and overlapping tags never compose. Alternatively, exact `paletteCycleId` plus exact `paletteCycleFrameId` emits one complete named-cycle period from that immutable source frame; it cannot combine with a tag, and malformed/missing/incompatible selectors fail before an approval job is created. A resolved GIF cycle whose `stepMs` is not divisible by 10 is likewise refused before approval because GIF cannot retain that exact timing; APNG and sprite-sheet schedules keep the authored milliseconds. Sprite-sheet JSON identifies each derived schedule entry and does not claim distinct canonical animation frames. Keyframed illustrations export their complete bounded timeline to GIF/APNG. Set `projectLinkId` without `format` to extract that cached source and convert it into a document-relative external link after approval. PSD and Tiled interchange remain native-scale structural exports.
- `job_manage`: owner-scoped list/inspect, wait up to 30 seconds, report a human-only approval dependency, or cancel. `start-batch` creates a 1–10,000 transaction durable job and returns its one-time opaque resume token; `resume-batch` securely rebinds it after a client or engine restart. Summaries omit raw results and private approval data.

Long work returns an explicit job ID. File approvals expire after two minutes. `allow-session`, `allow-always`, and explicit launch-time folder authority apply only to non-overwriting file requests. Canvas transactions themselves never require an open editor or approval; approval-dependent boundary work waits for UI attention.

For autonomous runs larger than one transaction, pass the batch `jobId`, `resumeToken`, and zero-based `sequence` on each ordinary `canvas_apply`. AIDraw accepts only the next sequence and requires a fresh `clientOperationId` for each new sequence. Repeating the recorded sequence/ID pair is an idempotent duplicate; reusing that ID at another sequence is a conflict. Progress becomes visible only after the canonical commit returns a transaction identity and the private ledger replacement succeeds. A failed ledger replacement leaves the prior sequence retryable, and startup reconciles a crash between canonical commit and progress persistence from the durable trace. Cancellation keeps transactions already committed (including the normal visible partial-stroke rule) and drops the remaining sequence.

## Conflict and load responses

Every mutable entity can carry `expectedRevision`. Non-overlapping additions may commit against a newer document revision, while stale replacements return `status: "conflict"` plus `conflict.entityId`, `expectedRevision`, `actualRevision`, and `retryable`. Retryable conflicts also return a `next` call to `canvas_observe`: re-observe canonical state, rebuild the same logical intent against the current revision, and use a fresh `clientOperationId` because the operation payload changed. Active human locks return `locked` with coarse occupancy and the same observe-first guidance. Full actor queues or the global playback budget return retryable `busy`. Reusing a committed client operation ID returns `duplicate` without applying it again.

Pixel and tile changes can use exact coordinate arrays or compact row runs:

```json
{ "kind": "pixel.cel.region", "spriteId": "sprite", "celId": "cel", "runs": [{ "x": 0, "y": 0, "length": 64, "index": 3 }], "expectedRevision": 4 }
```

`pixel.tilemap.region` uses the same shape with `gid`. One operation may address at most one million cells; overlapping runs are rejected. Runs drive sample-based playback, partial cancellation, lock conflicts, and exact per-actor undo without expanding the request. Tile GIDs retain Tiled horizontal, vertical, and diagonal flags.

- `pixel.image.quantize` for an embedded image asset using the document's area/OKLab/dither/alpha defaults;
- `pixel.project-link.embed` for one hash-checked external link and `pixel.project-links.pack` for every healthy external link, both guarded by the pixel-document revision;
- `pixel.image-collection.create` for 1–1,023 exact one-frame sprite IDs in explicit authored order, `pixel.image-collection.append` for one exact source at the next local ID above the collection span, `pixel.image-collection.source.replace` for one exact existing sparse tile plus one unused exact source, `pixel.image-collection.source.remove` for one exact tile proven unused across bounded map-cell, tile-object, retained-animation, tile-stamp, and Wang-reference checks, and `pixel.image-collection.tile.move` for one exact non-highest tile plus one unused destination inside the unchanged authored span. All five lower into existing canonical asset/map/stamp replacement operations, never copy/delete sprite pixels, synthesize an atlas, or ask the caller to calculate a GID. Replacement preserves the addressed local ID and complete tile metadata; removal deletes only that tile record, leaves a sparse gap, refuses the final source, and never cascades or rewrites a raw GID. Movement preserves the complete source/metadata record while rewriting every exact proven animation, Wang, map-cell, tile-object and reusable-stamp reference, retaining transform flags, coordinates, order, first GID and span; highest, occupied, same or out-of-span destinations and ambiguous ownership refuse before mutation. Replacement/removal recompute only the nominal maximum source envelope, while movement leaves it unchanged;
- `pixel.tile-object.create` for one exact attached tileset/local ID, writable object layer, map point, optional permitted H/V/diagonal flags, and caller-owned new object ID. It derives the raw GID and default source dimensions through the shared human planner; finite and sparse-infinite orthogonal or isometric image collections require one exact non-gap sprite source and carry all collection-source revision/dimension guards. The request must stand alone under exact document/map/tileset revisions and lowers to one existing complete-map replacement;
- `illustration.objects.align` with artboard/selection/key-object targets;
- `illustration.objects.distribute` on x or y;
- `illustration.material.apply` with the `polished-gold` editable material recipe;
- `illustration.gradient.set` with 2–32 ordered color/opacity stops and exact local-space geometry;
- `illustration.text.content.set` and `illustration.text.style` for content changes that preserve ranges and exact character-range typography;
- `illustration.image.crop` for display-space rectangle crops, centered aspect crops, and exact non-destructive reset without resampling or stretching;
- `illustration.object.filters.replace` for ordered, non-destructive brightness/contrast/saturation/hue/blur on vector, path, shape, text, stroke, or image objects (`illustration.image.filters.replace` remains a compatible image-only alias);
- `illustration.layer.filters.replace` for the same ordered adjustments on an isolated paint/vector/group-layer composite;
- `illustration.object.mask.set` and `illustration.layer.mask.set` for reference-safe assignment or clearing of editable path/layer masks;
- `illustration.animation.settings.replace`, `illustration.animation.keyframe.upsert`, and `illustration.animation.keyframe.delete` for revision-checked transform/opacity/visibility poses with linear, hold, or ease-in-out interpolation;
- `illustration.path.boolean` for exact Paper.js union/subtract/intersect/exclude over transformed compatible shapes and paths;
- `pixel.frame.duplicate`, `pixel.frame.move`, `pixel.frame.cels.link`, `pixel.frame.duration.set`, animation-tag upsert/delete, and per-frame palette overrides;
- `pixel.stamp.place` and `pixel.tile-stamp.place` for reusable exact indexed/GID stamp placement and optional transforms;
- `pixel.map-object.upsert` and `pixel.map-object.delete` for typed rectangle/ellipse/polygon/polyline object-layer authoring in map-pixel coordinates;
- `pixel.tileset-collision.upsert` and `pixel.tileset-collision.delete` for typed per-tile collision geometry and custom properties;
- `pixel.wang-set.upsert|delete`, `pixel.wang-color.upsert|delete`, and `pixel.wang-tile.assign` for validated edge/corner/mixed terrain authoring. Against an image collection each must be one sole request with the observed document revision, and the replacement retains exact sparse source/resolver truth through canonical admission;
- `pixel.wang-terrain.stroke` for one exact paint/erase request against an observed map, tile layer, attached tileset, Wang set/color, 1–65,536 ordered signed points, and current layer revision. For an orthogonal or isometric image collection it is a sole request and also carries the observed document revision; every Wang local ID must own an exact sprite source and resolve back through the attached production range. Finite maps retain their bounds while sparse-infinite maps admit safe signed points. The shared all-or-nothing planner emits one ordinary `pixel.tilemap.set`; missing final signatures/sources, gaps, shadows, foreign neighboring GIDs, stale identities/revisions, out-of-map points, and already-matching strokes return before canonical mutation;

- `illustration.path.node.move|insert|delete|convert` and `illustration.path.closed.set`; request `canvas_observe.pathObjectId` first for revision-labelled anchors and in/out handles.
- `illustration.path.arcs.convert` for exact SVG elliptical-arc conversion into editable cubic segments without dropping subpaths silently;
- `illustration.path.split` for an interior open-path cut or a lossless closed-path opening, and `illustration.path.join` for explicit or nearest-world-endpoint joining across object transforms;
- `document.fragment.import` for a fragment returned by `canvas_observe.fragment`, with optional illustration target layer and x/y offset.

Path booleans use the same exact shared Paper.js kernel in renderer and headless execution. Large multi-stage work should remain semantically partitioned so progress, cancellation, undo, and attribution are understandable.

`aidraw:variantGroup` (tile property) and `aidraw:variantSeed` (map property) are AIDraw-namespaced custom properties, not standard Tiled random-brush behavior. Tiled JSON/XML export retains them as ordinary typed properties, but no external editor interpretation is promised. UI and `pixel.tile-variants.paint` use the same coordinate-stable weighted choice; advancing the persisted seed changes subsequent choices only, while already painted GIDs remain exact.

Semantic Wang strokes deliberately do not consume that mutable map seed. Their weighted selector is initialized from a versioned exact logical intent containing the canonical document/map/layer/tileset/set identities, color, paint/erase mode, and ordered points; actor identity and `expectedRevision` are excluded so an observe-and-retry does not reshuffle an unchanged intent. The admitted layer revision is still checked before planning and again by the canonical reducer, and every nonzero affected GID must resolve back to the selected attached tileset. This is deterministic lowering into the existing reducer, actor history, lock, replay, persistence, and Tiled-GID path—not a new stored operation kind or recursive terrain synthesizer.

### Illustration observation allocation boundary

An illustration PNG region avoids the complete artboard only when every visible dependency is in the exact integer-aligned solid-rectangle subset. It uses a four-pixel-expanded local backing and raw crop. Curves, paths, text, images, gradients, strokes, rounded/fractional/transformed geometry, masks, paint content or cache, opacity/blend isolation, and effects retain full-artboard rendering plus raw crop so canonical pixels do not change. This is an internal allocation choice under the existing observation request/output limits, not a generic region-rendering, save/export, interchange, redaction, or foreign-format promise.
