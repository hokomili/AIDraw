# Architecture

## Process ownership

`EngineRuntime` is the canonical, BrowserWindow-independent owner of open documents, active-document identity, the transaction reducer, per-actor histories, locks, jobs, persistence, recovery, durable traces, credentials, supervised utility workers, and the localhost MCP endpoint. It runs in the Electron browser process but does not require a renderer. The React editor is an attachable client that receives immutable, monotonically ordered workspace snapshots through a narrow preload facade and keeps only optimistic pointer previews and UI state. It subscribes before bootstrap hydration and rejects an older reply/event, so an asynchronous tab response cannot replace newer canonical state. It cannot access Node or Electron directly.

The first process for a user profile takes Electron's single-instance lock. `<AIDraw executable> --headless` starts only `EngineRuntime`; a later ordinary launch signals that owner to create or focus an editor window. The browser process treats a loaded main frame—not merely an extant native shell—as attached. An initial renderer-load rejection, renderer-process exit, later non-aborted main-frame load failure, or show request that finds destroyed/crashed renderer contents detaches only that editor and may rebuild one fresh window against the same `EngineRuntime`. A terminal event settles the lifecycle even if the original load promise does not; replacement begins only after the stale native shell is confirmed destroyed, and create/bind/load/reveal/destroy exceptions fail closed. Confirmed detach clears the sole renderer's transient human gesture locks so headless agents cannot remain blocked by a gesture that no client can finish, and renderer IPC cannot admit another human lock while attachment is false; neither rule cancels canonical transactions already admitted by the browser process. A full-document reload temporarily detaches that renderer document and visual playback while retaining the trusted native shell; successful completion, or a healthy load stop after `ERR_ABORTED`, reattaches it without replacement. A tentative close keeps the same trusted renderer identity and locks until Electron confirms closure or cancellation; cancellation therefore resumes the healthy renderer without dropping an in-flight lock release, while confirmation performs the detach and clears remaining locks. Concurrent show requests coalesce across loading and wait across a closing shell; a renderer failure after that wait begins wakes the explicit show without reopening an otherwise intentional close. One explicit show intent permits one automatic retry, while another consecutive failure stays headless until a later explicit show rather than looping. Pending or completed engine shutdown suppresses opening; if shutdown itself fails, an interrupted retained retry may resume. No profile/cache deletion, engine restart, document/history mutation, or durable lock migration is part of this window contract. Closing the last window disables visual-delay scheduling but deliberately leaves the process and MCP engine alive. **File → Quit AIDraw Engine** or `--quit-engine` is the explicit full shutdown. Guided client setup registers headless startup through Windows login items, macOS login-item launch detection, or an XDG autostart entry on Linux.

Start-at-login mutations serialize in invocation order within the process. Windows and macOS retain their native Electron login-item calls. Linux enablement writes the complete XDG desktop entry to a unique same-directory mode-`0600` temporary, flushes and closes it, then atomically replaces the named entry; disablement removes that entry in the same queue. A failed replacement leaves the prior entry and later queue usability intact. This is a deterministic process-local lifecycle, not cross-process/multiple-instance coordination, directory-fsync/power-loss durability, expanded desktop-environment compatibility, or packaged login/reboot evidence.

Application settings and diagnostics that do not belong inside artwork use bounded atomic stores under the engine user-data directory. Within one `EngineRuntime`, reusable-preset and interchange-report reads and writes serialize in request order. Each mutation builds copied state, flushes a complete private same-directory temporary, atomically replaces the destination, and installs the copy only after replacement; a failed replacement leaves the previous disk and live state intact. This is process-local serialization, not cross-process or multiple-store-instance locking, directory-fsync durability, or a new byte ceiling. Reusable document presets retain strict `NewDocumentOptions` values without document names. Interchange diagnostics retain the latest 200 actor-attributed import/export outcomes, exact addressed paths, adapter warnings, raster fallbacks, and bounded structured fidelity reasons, and can be exported as standalone JSON without modifying a drawing. The additive version-one reason list uses closed codes plus exact document/layer/object identity; older reports normalize a missing list to empty. Currently only evidenced SVG/PDF/PSD export outcomes plus exact PSD import blend-mode substitutions populate it, so it is not a comprehensive adapter-loss ledger. A renderer recovery boundary can also write one user-addressed, bounded local diagnostic with runtime and sanitized tab/job/MCP summaries; it deliberately omits document content, assets, prompts/results, task IDs, tokens, and credentials.

Workspace layout follows the same private main-owned boundary rather than the canonical document model. One strict version-two value stores whether the inspector is collapsed, its 260–520 px expanded width, and whether the tilemap Layers panel's Map setup disclosure is expanded. Strict version-one inspector files migrate by retaining both predecessor fields and supplying the new collapsed disclosure default; malformed/partial/unknown current state is rejected as a whole. `EngineRuntime` loads that complete value before renderer bootstrap; the Zustand client installs it before `loading` clears, so an editor replacement cannot publish compiled defaults over durable intent before the canvas mounts. Missing state uses the established expanded 318 px inspector and collapsed Map setup defaults, while invalid state emits one bounded advisory. Saves serialize through private same-directory atomic replacement; a failure retains prior durable bytes, keeps the live renderer choice usable, and allows the next intent to retry. The CSS grid consumes a renderer-derived effective width: at compact content widths it admits no more than the existing 286 px inspector and always preserves the 632 px minimum canvas floor, without rewriting a wider saved value. Resize input starts from the shown width and is bounded by the current presentable maximum: compact shrink intent responds immediately, while unpresentable growth leaves a wider saved value unchanged; ARIA exposes the shown/saved distinction and viewport-specific Home/End range. Inspector collapse retains the saved width and synchronously clears the active resize session before releasing pointer capture, so later terminal events cannot persist stale preview state. A named top-bar route remains available when the sidebar is absent; its default is Ctrl/Cmd+Shift+I and the bounded shortcut preference below may change that renderer-owned route. Focus moves to the active inspector tab on reopen and back to the visible trigger on inspector collapse. In a tilemap Layers panel, the always-visible layer tree remains the primary workflow; one native Map setup button reports finite versus sparse-infinite state, orientation, cell extent, and tile size while its lower-frequency geometry/property controls remain mounted but hidden when collapsed. Pointer or Enter/Space recovers every action, truthful expanded state names the controlled region, the live summary is its accessible description, and collapsing from a descendant moves focus to the trigger before hiding it. The predecessor **Reset inspector layout** action deliberately resets only inspector collapse/width and retains the disclosure choice; the Map setup trigger controls that choice. The separator, reset, disclosure target, icon, and copy reuse established density tokens. These adapters change no artwork, revision, history, advisory, native/export byte, canvas transform, or agent authority, and they are not arbitrary docking, multiple named workspaces, broad panel redesign, or tool-rail customization.

Primary pixel-workspace text reflow is a renderer presentation contract, not another saved workspace preference. The shared body/label/caption values are expressed as `rem` ratios derived from the established 12/11/10 px tiers at a 16 px root; a 32 px root therefore yields exact 24/22/20 px text without applying `zoom`, transforms, or a canvas scale. Fixed content-window, shell, tool-target, status, and 138 px timeline geometry remain physical CSS pixels. Instead, document tabs, active context controls, the tool rail, inspector navigation/content, pixel floating controls, timeline/tags/frames, and status/zoom own bounded local scrolling. Inspector children acquire a root-relative readable minimum; the tab strip keeps the predecessor 52 px height at the ordinary root but reserves 71 px at the enlarged root for its icon, label, and non-overlay horizontal scrollbar. Timeline labels use root-relative fit rules, while frame cards keep their ordinary 62 px width and expand to 142 px at the enlarged root so metadata stays contained and the frame strip absorbs the extra width through its existing local scroll. Focusable descendants retain DOM order and browser focus scrolling, the named inspector collapse/reopen and Skip to canvas routes remain outside hidden content, and a passive compact viewport still cannot rewrite the wider saved inspector preference. This contract proves only deterministic source/CSS behavior at the declared root sizes, not how Electron, an OS, browser zoom, or assistive technology selects or renders that root.

Consented automatic agent-client setup is a separate external user-config boundary. Automatic Codex, Claude Code, OpenCode, and Antigravity updates serialize in invocation order within one process, re-read the selected config before mutation, preserve each existing byte version in a distinct private timestamp-based backup, and publish the complete private config through the same flushed atomic replacement primitive. Failure preserves the prior config and leaves the queue retryable. The persisted config result is authoritative; start-at-login is a subsequent best-effort action, so its failure retains `configured` status and the config/backup paths while telling the user to start AIDraw manually. AIDraw does not roll back a client config after that separate failure. This establishes no config-size ceiling, cross-process/multiple-instance lock or compare-and-swap guarantee, directory-fsync/power-loss durability, live-client restart/discovery, or packaged acceptance.

All committed changes are `CanvasTransaction` values over the application-owned model in `packages/core`. Every canonical operation kind has a bounded runtime payload schema. The reducer verifies document identity and expected entity revisions, produces inverse operations, increments revisions, and records attribution. Layer/object replacements may change entity content but not ordered layer, vector-layer, or object-group membership; those structural edits must use the dedicated add/move/delete operations so their exact positions remain invertible. File formats and renderer libraries are adapters; their private serialization never becomes the native model.

## Concurrency

Pixel fill and replacement are one-shot previews. Pointer cancellation or Escape synchronously clears every transient gesture state, then best-effort releases each distinct lock that eventually resolves, and never invokes the commit path.

Human gestures preview in the renderer and acquire object or pixel/tile-region locks from pointer-down through commit. Multi-object translate/scale/rotate holds one object-set lock and commits revision-checked replacements as one human transaction. Canonical apply, undo, redo, and checkpoint-restore requests serialize in invocation order for each document, while different documents remain independent. An async transaction admission rechecks the original open-document incarnation and human lock state before commit, so later same-document work cannot overtake it and a delayed old request cannot mutate a replacement carrying the same ID. This mutation queue is separate from revision-bound native-save scheduling: saves still snapshot at their own invocation and permit later editing. Agent playback is scheduled round-robin across at most four visible lanes when an editor is attached; their final commits pass through the same per-document queue. With no renderer, the same validated transactions commit immediately instead of sleeping for invisible animation. A session may queue four transactions, a request may contain 256 operations/2 MiB, and visible work shares a one-million-sample budget. Schema-shaped but non-JSON-serializable transactions return a canonical conflict before size accounting or mutation. Compact row runs are charged by addressed cells rather than run count. Unrelated operations proceed; stale/conflicting operations return retry guidance and coarse human occupancy.

In-canvas illustration text editing is a bounded content transaction over that same model, not a second text renderer. Select-tool double-click or keyboard Enter opens one textarea only when the text object and its object/layer ancestors are visible and unlocked. Its CSS matrix composes canonical ancestor-group and object affine transforms with the current viewport; the first-character range supplies the editing font while Canvas remains visual authority for mixed ranges. The derived style is memoized across draft keystrokes, so hierarchy discovery does not become per-character document work. Blur or Ctrl/Cmd+Enter rechecks the current hierarchy before one `replaceStyledText` object replacement at the captured revision; Escape discards it, while a conflict or newly hidden/locked hierarchy keeps and refocuses the draft. Long-lived collaboration locks and per-keystroke transactions were rejected because optimistic revision plus commit-time eligibility preserves intent without think-time lock ownership or history spam. A selection-only pointer click now releases its acquired lock without a zero-distance move transaction. Range styling stays in the inspector; no schema, layout, render, font, or interchange contract changes.

Keyboard discoverability and the bounded editable subset share one registry rather than maintaining separate rail, guide, route, or ARIA maps. The strict complete registry contains all 39 displayed mode-scoped tool actions—19 illustration and 20 pixel—plus the renderer-owned inspector toggle. Both rails are derived from those tool actions, so guide rows, live mode routing, labels, titles, and `aria-keyshortcuts` cannot silently omit a displayed tool. A chord identifies at most one action in an overlapping scope, while equivalent tool chords remain legal across disjoint modes. Tools admit one unmodified letter or Backslash; the inspector admits Ctrl/Cmd plus one letter with optional Shift. Capture rejects invalid, duplicate, lifecycle-reserved, or fixed-handler-overlapping values before the live map changes and names the conflict/reason. File/history/clipboard/Select All remain fixed through Electron's native menu and existing renderer handlers. Every actual shifted/unshifted renderer overlap is reserved: Ctrl/Cmd+Y is the native-menu Redo accelerator, while Ctrl/Cmd+Shift+Z is the fixed renderer redo alias. F1/?, editing/cancel keys, and focus navigation stay fixed recovery routes.

Shortcut preferences use a separate main-owned private version-two file. `EngineRuntime` loads its complete map before renderer bootstrap; Zustand installs it before `loading` clears, so replacement shells never publish compiled defaults first. Missing state uses all 40 defaults. The exact predecessor version-one action set is parsed with its old completeness, reservation, and conflict rules; every valid old chord is copied unchanged. Each newly introduced tool then receives its declared default if free. If an old remap owns that default, allocation reserves every later new tool's still-available declared mnemonic before choosing the first deterministic remaining mode-local chord, so an earlier fallback does not unnecessarily displace a later default. The migration does not rewrite the predecessor file merely by reading it; the next deliberate save writes version two. Partial, unknown, malformed, reserved, conflicting, or wrong-version current state is rejected as a whole and yields one bounded recovery advisory. Saves serialize through private same-directory atomic replacement; a failed save preserves predecessor bytes, keeps the live renderer mapping usable, and permits retry. Restore defaults submits the complete 40-binding default value through that same path. Modal and editable-target guards remain ahead of live action routing. The vertical tool rail retains one roving Tab stop, F1/? remains an always-fixed guide route, and the named Skip to canvas path is unchanged. This preference has no document/reducer/history/native/export/MCP authority and adds neither keyboard drawing/manipulation nor tool-setting or native-menu accelerator alternatives.

Open-document navigation follows the same renderer-only discipline. One pure horizontal index helper supplies wrapping Left/Right and edge Home/End movement; the focused destination uses the existing document activation path because switching is immediate and local. The active tab alone is in the tablist's ordinary Tab sequence. Its close affordance is a sibling native button rather than a nested interactive descendant, and a successful active close restores focus after the published workspace snapshot identifies the replacement tab. Inactive close buttons remain pointer-operable but stay outside sequential focus until their tab is active. No lifecycle, save prompt, all-documents menu, direct shortcut, document schema, or engine contract changes.

Renderer popovers own focus without becoming modal. The All-documents disclosure remains an ARIA menu: opening focuses the active document, one pure vertical index helper wraps Up/Down and resolves Home/End across document entries followed by the existing batch commands, and selecting or escaping returns the trigger. The Export disclosure is instead a named non-modal dialog because its scale/range selects and format buttons are not a homogeneous menu; opening focuses its first available control. Both dismiss on outside pointer interaction, while capture-phase Escape closes, restores the trigger, and stops before background canvas handlers. No focus trap, typeahead, command, export, batch, or canonical-state layer is introduced.

Clipboard interchange is a main-process workflow adapter over canonical fragments and the existing raster utility supervisor. Whole-artwork copy builds a bounded editable fragment, asks the supervised export lane for its PNG, and writes standard text/PNG plus one private HTML envelope. Pixel bitmap paste asks the supervised quantization lane for canonical changes. Exact sprite-selection copy uses that same versioned, SHA-256-bound HTML envelope without inventing a custom OS MIME: it carries one bounded relative-cell grid, its effective source-frame palette, and source-document identity through two explicit preload methods. Main also materializes that grid into an isolated one-frame sprite and asks the supervised export lane for a 1× PNG of the exact bounds; absent irregular-mask cells remain transparent, and native decode must retain the planned geometry before the complete text/HTML/PNG write succeeds. A renderer rereads the system clipboard on focus and every paste, and Cut waits for that complete write before deleting.

The sprite-selection reader gives private ownership strict precedence. A valid private `pixel-selection` returns unchanged; malformed/checksum-invalid/unsupported private data or a valid whole-artwork fragment fails explicitly without reading a bitmap. Only an absent marker reads a PNG. Main confines Electron `nativeImage` to OS ingress/egress, requires canonical PNG bytes plus matching native/header geometry under the established 8,192-side/16MP and 1,500,000-byte editable-asset ceilings, and sends no image object or encoded bytes into the renderer. Requested PNG paste rereads the active document, selected sprite, frame, layer/cel and linked exposure, then quantizes the native-size rectangle through the supervised lane using the effective frame palette and document alpha/dither defaults with transparent cells included. The existing utility and cel-operation boundary limits that conversion to one million cells. Main returns only the bounded indexed operation/selection plan plus the exact document revision from which every planning dependency was read. After the renderer's human region-lock wait, the existing human transaction carries that revision as an optional canonical transaction precondition while the cel operation retains its own expected revision. `applyTransaction` compares the document precondition before any operation; palette/override/default/layer/frame/link drift—or any other intervening canonical revision—therefore preserves the newer edit and refuses the stale paste with no activity/history. The generated inverse deliberately omits this one-shot admission guard, while trace/history replay rebases a retained guard to the current document alongside existing entity revisions. Private fragment operations never set it and keep their predecessor behavior. Renderer reports clipping and selects every admitted bitmap cell only after commit. PNG adds no palette entry: it cannot preserve the private irregular mask or palette identity, and transparent pixels intentionally become index-0 clears. Private paste retains its existing origin, exact cross-sprite color reuse/append, linked-cel resolution, and one palette-plus-cel transaction; marker-absent PNG defaults to `(0, 0)` when there is no cursor. Tile selections remain project-local because raw GIDs are not portable without tileset identity and rebasing policy. The private parser still bounds HTML before base64 decode, requires exact canonical base64 and version/hash agreement for current envelopes, and reads the exact legacy marker. This creates no second canonical model, generic IPC or filesystem authority and does not promise arbitrary rich-format preservation, cross-process tile/GID transport, or native/packaged cross-application clipboard behavior.

Checkpoint comparison also uses the supervised export lane, but remains a renderer-facing snapshot workflow rather than canonical state. The current document and stored checkpoint are cloned before work begins, then rendered sequentially so the single utility lane owns at most one native comparison task. Main-process admission requires a static PNG whose header geometry exactly matches `renderDocumentDimensions` for that snapshot before building the existing data URL. The ordinary export path deliberately preserves the comparison's established whole-raster allowance; substituting the observation codec would impose its separate 4 MP result ceiling. Invalid worker output rejects the comparison rather than producing a broken image. This changes no checkpoint identity, revision, merge candidates, adaptive-preview policy, or UI result shape.

Generation comparison has a separate in-memory source contract from provider outputs. If an edit request names a retained canonical raster, the manager repeats the pure byte/hash/MIME/header/display-geometry checks and forwards its exact PNG/APNG/JPEG/WebP/GIF bytes with the truthful MIME; it does not ask Electron to decode, freeze, or transcode that source. If no source is selected, it clones the current document, checks the established whole-raster dimensions, and asks the supervised PNG export lane to render that snapshot. Main-side admission copies the result and requires a static PNG whose header geometry exactly matches the snapshot before a job exists or a provider can be called. An ordinary renderer failure therefore fails closed without chargeable dispatch. This changes no provider input, network authority, canonical document or asset, acceptance normalization, persistence schema, or adaptive-preview policy.

Sprite-sheet selection is also a supervised raster workflow. The worker reads one explicitly selected or approved absolute path under the existing 1,500,000-byte retained-source ceiling, derives PNG/JPEG/WebP identity and display geometry from the bytes, verifies that the pinned decoder agrees, and returns a no-enlarge preview capped at 640 pixels wide for landscape or 480 high for portrait. Main admits only a canonical static PNG below 4 MiB whose decoded geometry matches that deterministic preview size; malformed output retires the producer. A human selection retains the worker-derived SHA-256 and MIME for an exact recheck when the worker re-reads the file for import. An approved-agent import has no preview step and derives the same identity inside its import worker. Slicing coordinates use display-oriented dimensions, so EXIF-rotated JPEG grid geometry agrees with the pixels users see, while the original bytes remain the embedded source. Electron `nativeImage` remains only at unrelated OS integration boundaries; selection capacity/expiry, slice/quantization semantics, and path authority are unchanged.

Autonomous work larger than one transaction can use a durable numbered batch. Its private ledger contains only a hashed resume token, document/sequence/progress, and committed operation/transaction IDs; canonical drawing data remains in the ordinary journal and trace. Each new sequence requires a fresh operation ID within that batch, while the recorded sequence/ID pair remains the exact idempotent-retry identity. Startup admits only exact version-one writer-shaped roots and records, discards invalid records, clears old in-memory resumability before installing an invalid/missing replacement, and reconciles the narrow crash window between a successful reducer commit and progress persistence from the durable trace. Every state transition is copied first, flushed through a unique private temporary, atomically replaces the ledger, and only then becomes live or publishes job progress. A replacement failure therefore leaves the prior live/disk state authoritative and retryable. This is process/filesystem ordering and replay integrity, not a directory-fsync or power-loss guarantee; the opaque token still allows ownership to rebind to a new authenticated MCP session.

Cancelling an active lane slices strokes/pixel changes at the current reveal position, commits that prefix with `partial` activity, and drops the rest. The prefix remains one attributed undoable transaction. Human and each MCP actor have independent in-memory undo/redo stacks; recovery deliberately starts new stacks rather than presenting a partial persistent history.

Each history entry retains the logical targets of both its committed transaction and generated inverse. Monotonic expected revisions are rebound only when that actor invokes the current top entry and no later foreign transaction touched an overlapping target. Disjoint object/cel/layer histories remain independently undoable; a foreign overlap permanently blocks crossing that entry, and an explicitly unrecorded same-actor mutation creates the same barrier. A newer own edit made after foreign work can undo back to that foreign state but cannot cross it. Whole pixel-asset targets contain nested frame/cel/layer targets, while document-revision-guarded operations remain blocked by every foreign commit because their concurrency token is intentionally global. The snapshot disables undo/redo when its top entry is blocked, and direct callers receive the attributed conflict. Undo and redo commits are journaled, traced, and included in revision-based change observation. Blindly rebasing every inverse was rejected because it could overwrite another actor's work; automatic semantic merging or CRDT history is not claimed.

## Rendering and storage

Shared pixel-tool kernels cache indexed chunks, preserve ordered pencil revisits, rasterize symmetric integer ellipses, and return flood/replacement regions as canonical row runs. Floods cap the actual connected result at one million cells; replacements cap the inspected target at one million cells; both cap output at 65,536 runs and return no partial result. The interactive surface intentionally reads the visible composite for fill, wand, and replacement while semantic operations read their addressed cel. Sprite/tile selections and reusable pixel/tile stamps expose separate clockwise and counterclockwise quarter-turn actions, but both directions use the same exact indexed/GID kernels as semantic execution; no renderer-local rotation path or direction toggle owns different geometry.

Seamless sprite Wrap edit is a session-local coordinate adapter, not another storage or operation model. Repeated-copy points retain their raw drawing order through brush, shape, symmetry, and pixel-perfect processing, then one shared Euclidean-modulo kernel maps them into the finite canonical sprite rectangle before the existing indexed cel operation. Reusable stamps and bitmap text use the same mapping; repeated-copy sampling and region seeds map once before reading. The existing full-sprite human lock, cel revision guard, single transaction, writer last-write ordering, actor undo, palette validation, replay, native storage, and export remain authoritative. Rectangle/lasso geometry and flood connectivity do not become toroidal, and agents continue to submit exact canonical coordinates through AGT-11 rather than receiving a renderer-mode parameter.

Sprite symmetry is human-local tool configuration rather than authored document state. One pure contract reflects integer pixel-center coordinates around a horizontal X or vertical Y axis admitted on the half-pixel grid, emits variants in fixed original/horizontal/vertical/both order, and deterministically retains the last payload for duplicate addressed cells. The centered axes `(width - 1) / 2` and `(height - 1) / 2` therefore preserve the former reflection byte-for-byte. Freehand/shapes, dither, lighten/darken, reusable sprite stamps, and bitmap text share that expansion before the existing finite filter or Wrap adapter; read-only sampling and one-shot region seeds retain their established single addressed point. Guides convert an axis coordinate to the canvas pixel-center line `(axis + 0.5) × scale`, so browser CSS scaling stretches artwork and guide together without introducing another coordinate system.

The main process owns one strict version-one symmetry preference with a global None/Horizontal/Vertical/Both mode and at most 128 axis bindings keyed by exact bounded document ID, sprite ID, width, and height. Bindings admit only canonical-sized dimensions, and both axes must be in range on the half-pixel grid. An identity or dimension mismatch resolves visibly to centered defaults; it never clamps an old binding onto different artwork. `EngineRuntime` loads this file with the onion preference before editor bootstrap and flushes both stores on shutdown. Complete mode-`0600` same-directory atomic replacements serialize in invocation order; malformed state falls back as a whole with one bounded advisory, and a failed replacement preserves the prior main-owned/file value while the renderer keeps its usable intent and can retry. The narrow preload route carries only this complete value. No reducer, transaction, activity/history, native/archive/export field, or MCP authority observes it. Cross-process preference-file coordination, directory-fsync/power-loss durability, native preference acceptance, and packaged guide/pointer behavior remain outside this source/headless contract.

Ordered-dither configuration is likewise human-local tool state rather than indexed artwork. One strict version-one private value owns the current 2×2/4×4/8×8 matrix, coverage, normalized matrix-local X/Y phase, at most 32 named presets, and optional active-preset identity. Each phase field owns an exact keyboard draft so blank, sign-only, invalid, and unfinished multi-digit text cannot mutate live preferences; blur or Enter admits a signed whole-cell integer bounded to ±8,192, normalizes it with exact Euclidean modulo, and replaces the draft with the visible matrix-local result. Escape cancels, while changing matrix size discards any stale draft and produces one immediate visible phase in the new matrix. Presets carry only matrix, coverage, and normalized phase. Base/mix palette indices and colors remain explicit renderer/document context and never enter the preference file. The renderer applies symmetry and selection policy as before, maps Wrap edits to canonical coordinates, and supplies the same effective phase to preview and the existing revision-checked cel transaction.

`EngineRuntime` initializes the dither store with the onion and symmetry stores before editor bootstrap, and the loading screen prevents renderer defaults from becoming authoritative first. Complete private atomic replacements serialize in invocation order; missing state uses the 4×4, 50%, phase-0,0 default with no presets, malformed state admits no partial field and emits one advisory, and a failed replacement preserves prior durable bytes/main-owned state while live renderer intent remains usable and retryable. The narrow typed route carries only the complete strict preference. Settings and preset management add no reducer, lock, transaction, activity/history, native/export field, or MCP authority. Cross-process file coordination, directory-fsync/power-loss durability, and packaged preference/visual acceptance remain outside this source/headless contract.

Sprite animation tags remain one flat ordered canonical list of exact IDs and independent inclusive frame ranges. A shared span resolver converts their endpoint IDs into authored ordinals and returns every tag in stable tag order; it never infers parentage, masking, priority, or a combined schedule. For the per-frame presentation, one difference array computes every exact membership total and a skip-over-full worklist retains at most the first four authored-order span references per frame, bounding retained references and span visits without a new schema limit. Those summaries drive duplicate-disambiguating range/direction labels, exact accessible remainder text, and one roving keyboard toolbar. Renderer preview selection stores the exact document/sprite/tag tuple and resolves only against the current sprite; a coincident ID in another canonical sprite cannot become selected, move the frame, drive playback, or enter the advisory. With no resolved tag, playback and advisory share the same full-timeline direction resolver: Forward unless global Ping-pong is enabled. An edit draft is likewise document/sprite-scoped, becomes unavailable and closes on a context change, and rechecks both scope and continued target existence before the existing complete-sprite replacement. The sequence kernel resolves one explicit current ID and applies only its forward/reverse/ping-pong traversal, preserving each canonical frame duration and source order. Human export uses the same scoped choice and derives both the visible selector value and submitted ID from the current exact resolution; a missing or context-stale tag therefore omits the selector and exports the full timeline. Authenticated MCP passes exact IDs, while batch and CLI first honor an exact ID and otherwise require exactly one case-insensitive name match. Missing or ambiguous explicit selectors fail before export/approval rather than falling through to the full timeline or first duplicate. Tag upsert/delete still replace the complete sprite through one revision-checked canonical asset transaction with exact inverse, and frame insertion/deletion/reorder retain the established endpoint normalization. No hierarchical schema, multi-tag/palette-cycle schedule, or second mutation authority is introduced.

Named palette-cycle export is a derived raster schedule, not canonical animation. One exact named cycle plus one exact sprite frame produces a single loop period whose entry count equals the inclusive palette range and whose step duration is the authored `stepMs`. Each derived entry keeps stored pixel indices unchanged and supplies the existing renderer/exporter with a shallow effective-frame palette whose colors are rotated by the shared forward/reverse index kernel. Frame-specific palette overrides therefore remain authoritative, while index 0 and colors outside the declared range are unchanged. GIF/APNG encoding retains the existing exact-normal-composite path, Canvas fallback, and nearest-neighbor scale. APNG keeps its 64-megapixel aggregate raw-frame ceiling; GIF keeps its established sequential-frame policy rather than acquiring a new aggregate rejection. APNG's millisecond time base covers every admitted cycle delay; GIF's centisecond field is used only when `stepMs` is divisible by 10, otherwise both UI and exporter fail closed instead of rounding.

Sprite-sheet output feeds those same derived entries into the established bounded square-ish PNG layout. Its JSON uses distinct `cycle-step-N` keys plus an explicit ordered-entry list; every entry records the one canonical `sourceFrameId`, exact duration, presentation scale, and palette offset, while the schedule records cycle ID/name/range/direction/`stepMs` and source-frame ID/name. It deliberately omits timeline/tag scheduling metadata rather than presenting those entries as separate canonical frames. Ordinary full-timeline/tag sheets keep their predecessor geometry, metadata and pixels. The editor sends exact selected IDs and disables incompatible formats; the CLI resolves each cycle/frame selector by exact ID or one unambiguous case-insensitive name; MCP accepts exact IDs and includes them in the human approval review. Every surface requires the complete pair and refuses cycle-plus-tag or unsupported formats. After exact cycle/frame resolution, CLI classifies a non-centisecond GIF schedule as a validation refusal before publication and MCP rejects the same schedule before approval-job creation; the exporter still revalidates independently before any write. No revision, activity, undo, lock, cel, palette, tag, duration, schema, or agent mutation authority changes; combining the frame timeline with one or more palette cycles remains an intentionally undefined scheduling problem.

The bundled `bitmap-font-tiny-5x7` materialized into a newly created pixel document is a fixed hand-authored asset, not host-font rasterization. ## Security boundary

BrowserWindow uses sandboxing, context isolation, no Node integration, no webviews, denied permissions/navigation, CSP, and hardened Electron fuses. Production renderer assets are served only from the restricted `aidraw://app` protocol, with `file://` extra privileges disabled. IPC validates the exact sender/main frame. Hosted keys and the MCP token use Electron `safeStorage`: DPAPI on Windows, Keychain on macOS, and a supported system secret store on Linux. AIDraw refuses Linux `basic_text`. Their encrypted files share one **256 KiB** handle-bound admission before JSON parsing or decryption; over-limit or observably changing provider ciphertext follows the existing empty/unconfigured recovery, while the MCP token follows its existing corrupt-secret rotation path. No prefix reaches `safeStorage`. One local credential-store instance serializes token reads and rotations. It accepts only the exact version-one three-field envelope, canonical nonempty base64 ciphertext, and a decrypted canonical 32-byte base64url token; every other admitted file rotates. A new token is returned only after its complete private same-directory temporary has been flushed, closed, and atomically replaced, so concurrent callers converge and encryption/replacement failure preserves prior bytes. This is process-local ordering, not cross-process or multiple-store-instance locking, directory-fsync durability, or packaged backend evidence. The explicit headless connection handoff contains that token in plaintext and is therefore admitted only at the documented nonempty absolute path and published through the same private flushed atomic replacement primitive: a reader sees the prior artifact or one complete new version, replacement failure preserves the prior bytes, and the final POSIX entry is mode `0600`. Atomic rename replaces the named entry rather than writing through its former inode; no working-directory-relative destination, parent-path canonicalization, cross-process handoff-writer lock, directory-fsync/power-loss, or packaged launcher evidence follows. Hosted-provider keys remain main-owned, are passed only in the typed request for the isolated provider worker, and are never returned to the renderer or MCP; the provider bridge exposes write/removal plus configured/stored/availability status only. Provider rotations are serialized and atomically replace an encrypted file requested with mode `0600` on POSIX, while explicit removal can delete ciphertext without decrypting it when the operating-system backend is unavailable. The separately scoped MCP connection-settings action may reveal its own token to the renderer. This ceiling does not cover unrelated user-data stores; native backend and packaged-interaction acceptance remain release gates.

MCP uses authenticated stateful Streamable HTTP on a persistent first-available port from 48200–48231. Initialization reservations and retained transports share one exact 32-session ceiling, so a concurrent 33rd initializer receives HTTP 429 instead of allocating another server/actor. Authenticated transport DELETE is the explicit capacity-release boundary: transport close idempotently retires presence, 128-bounded resource subscriptions, and session-scoped folder trust, while `session_manage leave` remains presence-only. Duplicate subscriptions do not consume another slot and unsubscribe frees one. The engine deliberately has no unestablished idle-eviction policy; shutdown closes every transport. Model mutations are safe to perform headlessly. Files are accessed only by explicit canonical paths; session/persistent folder trust can skip repeated non-overwriting prompts. Persisted trust is itself authority: startup accepts only the exact version-one writer object with a unique array of absolute NUL-free paths, canonicalizes the complete list before installing any entry, and replaces rather than accumulates the in-memory set. Invalid state grants nothing. The preferred-port file likewise requires the exact writer object and a numeric in-range integer before it can influence the numeric candidate scan. Both application-owned control files use private flushed temporary files plus atomic replacement. Persistent grants serialize, become active only after replacement succeeds, and drain before engine stop completes. No file signature or general settings-size ceiling is inferred. Every overwrite and every agent generation still requires prior authority, and such jobs remain pending until an editor attaches rather than weakening the boundary in headless mode.

The commit boundary replaces client-proposed entity revisions, creator IDs, and timestamps with authenticated actor/commit values, recursively including sprite layers, frames, and cels. Optional model/reasoning/task metadata is validated and persisted as client-declared attribution, not platform attestation. Undo/redo operates on the resulting trusted inverse so exact restoration is preserved. Generic canvas transactions cannot add or remove verified generation provenance. Embedded-asset deletion is rejected while image objects, paint tiles, linked previews, or provenance still reference it; an explicit ordered cascade remains possible and exactly invertible. Job enumeration is owner-scoped and sanitized before crossing MCP so result payloads and human approval details do not leak between sessions.

Inline assets do not grant filesystem authority, but they are still untrusted input. Only canonical base64 raster PNG/APNG/JPEG/WebP/GIF payloads are accepted, with a 1.5 MB decoded limit, SHA-256/length/MIME checks, safe header dimensions, an 8192 px side/16 MP limit, and a real codec decode before commit. Agent claims of a generated source are normalized to ordinary embedded data; verified generation status comes only from the engine-owned provenance path.

Addressed imports are likewise untrusted after file approval. Root files have format-specific byte caps; raster/PSD/PDF headers and decoded surfaces, animation frames, sprite-sheet expansion, Tiled layers/chunks/objects/tiles, and compressed layer output have explicit budgets. SVG/TMX/TSX reject DTD/entity declarations. Metadata, external tilesets, and source images may follow only realpath-resolved relative references contained within the approved root folder, preventing `..` and junction/symlink escapes without granting file enumeration.

Those existing compressed/source-file caps are enforced by one handle-bound reader before parser or native decode work. It first refuses non-regular paths without blocking on a FIFO, opens the approved path nonblocking, repeats regular-file and byte-limit checks on the actual handle, then reads at most that handle's declared size plus one byte. The sentinel detects observable growth after the check and is never returned; an observable short read likewise rejects shrinkage. Root/companion interchange files, sprite-sheet sources, native archives, palette files, and project-link relinks share this primitive with their unchanged 1 MiB through 512 MiB ceilings. It still returns one complete bounded buffer and therefore is not a streaming-parser, path-identity snapshot, arbitrary same-size mutation detector, or exact peak-memory claim. Realpath containment, dialog/agent authority, format detection, source retention, and canonical admission remain separate unchanged layers.

The product remains a local desktop engine/editor with concurrent localhost MCP sessions. Windows is the release-evidence baseline. macOS/Linux runtime abstractions, secure-storage policy, login behavior, Forge makers, and native CI jobs are implemented; Apple Silicon additionally has the exact-artifact independent Level 2 MCP + Computer Use PASS itemized in `MACOS_DEVELOPMENT.md`. Neither platform is promoted to a verified release target until hosted native, clean-machine/signing, and Level 3 release gates pass. Remote service tenancy, accounts/cloud sync/remote multiplayer, mobile, and web remain separate programs.

Targeted illustration observation has a deliberately conservative allocation adapter rather than a second rendering authority. One DOM-neutral predicate admits only visible, full-opacity, normal-composite, no-effect content from exact proven subsets: integer-positioned/sized square-corner rectangles, polygons, and stars with no visible stroke; and embedded PNG objects whose source dimensions, optional in-bounds crop, displayed dimensions, and placement are integers. PNG internal alpha and integer up/down/crop sampling remain the ordinary Canvas draw path. Structural object groups may add only integer translation; layers must retain the existing default nonisolating state. A paint layer is additionally eligible only when its structurally valid materialized cache covers every editable stroke. The main renderer translates the established Canvas work onto a four-pixel-expanded regional backing, scans that bounded paint index, decodes/copies only intersecting 256×256 cache tiles, and extracts the exact request with raw RGBA copy. Deterministic straight-edge, embedded-PNG, grouped, and materialized-paint matrices compare opaque/transparent full-artboard crops byte-for-byte. Candidate ellipse and rounded-rectangle curves produced real channel differences and therefore remain on the fallback, as do fractional geometry, gradients, visible strokes, arbitrary paths, text, non-PNG or incomplete image records, live paint tails, incomplete caches, masks, filters, opacity/blend isolation, rotation, scale, skew, and every other unproved curve or raster/spatial dependency. PNG alone is admitted because JPEG orientation/loss, WebP, GIF/APNG animation, and other decoder semantics have no equivalent exact matrix here. This preserves pixels, asset/decode authority, canonical strokes, cache validation, and model/interchange semantics while allowing a tiny request on a common maximum-artboard primitive, embedded PNG, or saved paint document to avoid a 64-megapixel allocation. No origin, spatial index, generic paint/vector/image clipping, broad raster compatibility, or save/export contract is inferred.

Within that exact regional path, the renderer still scans leaves in canonical order but skips a shape/image before Canvas path submission or asset decode when its conservative integer destination frame—including already-admitted structural-group translation—is disjoint from the expanded backing. Half-open intersection excludes only mathematically empty contact; unsafe accumulated arithmetic and any unsupported leaf remain included. This is an O(total leaves) work filter, not a persisted bound, spatial index, editor-viewport contract, or new rendering authority.

Transient sprite/tilemap overlay rendering reuses the canonical outward-rounded raster viewport but remains separate from artwork storage. One validated projection-aware filter conservatively tests orthogonal rectangles or isometric diamond bounding boxes. It derives an offset range for a horizontal compact run algebraically, so million-cell replay/fill records are not expanded or submitted to Canvas merely to be clipped; scale-aware raster padding protects selection stroke coverage. Point selections remain canonical arrays and are scanned once, retaining only visible candidates for the two marching-ant passes. Preview/replay order, colors, opacity, transforms, compact operations, selection state, and actor attribution are unchanged. This bounds drawing rather than inventing a spatial index or changing undo/playback semantics.

The editor's grid-surface decoration has a separate DOM-neutral planner. It intersects the complete scaled sprite/map surface with the visible viewport for globally phased checker cells and with a 64-pixel-expanded viewport for the existing 24-pixel blur/8-pixel-offset artboard shadow. The renderer shadows that one bounded source rectangle, clears shadow state, clips to the nominal surface, and submits the dark cells as one path. Freeform grid lasso state retains a synchronous exact outline only: consecutive samples discard a middle point solely when both segments are collinear and continue in the same direction. Cell rasterization moves to pointer release, chooses scanlines along the shorter bounding-box axis, and fails without changing selection above 4,096 vertices, one million candidate cells, four million Bresenham boundary steps, or safe integer coordinates. This introduces no approximate decimation, spatial index, canonical state, map-origin policy, or headless/export behavior.
