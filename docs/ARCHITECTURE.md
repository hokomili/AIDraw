# Architecture

## Process ownership

`EngineRuntime` is the canonical, BrowserWindow-independent owner of open documents, the transaction reducer, per-actor histories, locks, jobs, persistence, recovery, durable traces, credentials, supervised utility workers, and the localhost MCP endpoint. It runs in the Electron browser process but does not require a renderer. The React editor is an attachable client that receives immutable workspace snapshots through a narrow preload facade and keeps only optimistic pointer previews and UI state. It cannot access Node or Electron directly.

The first process for a user profile takes Electron's single-instance lock. `<AIDraw executable> --headless` starts only `EngineRuntime`; a later ordinary launch signals that owner to create or focus an editor window. Closing the last window disables visual-delay scheduling but deliberately leaves the process and MCP engine alive. **File → Quit AIDraw Engine** or `--quit-engine` is the explicit full shutdown. Guided client setup registers headless startup through Windows login items, macOS login-item launch detection, or an XDG autostart entry on Linux.

Application settings and diagnostics that do not belong inside artwork use bounded atomic stores under the engine user-data directory. Reusable document presets retain strict `NewDocumentOptions` values without document names. Interchange diagnostics retain the latest 200 actor-attributed import/export outcomes, exact addressed paths, adapter warnings, and raster fallbacks, and can be exported as standalone JSON without modifying a drawing. A renderer recovery boundary can also write one user-addressed, bounded local diagnostic with runtime and sanitized tab/job/MCP summaries; it deliberately omits document content, assets, prompts/results, task IDs, tokens, and credentials.

All committed changes are `CanvasTransaction` values over the application-owned model in `packages/core`. The reducer verifies document identity and expected entity revisions, produces inverse operations, increments revisions, and records attribution. File formats and renderer libraries are adapters; their private serialization never becomes the native model.

## Concurrency

Human gestures preview in the renderer and acquire object or pixel/tile-region locks from pointer-down through commit. Multi-object translate/scale/rotate holds one object-set lock and commits revision-checked replacements as one human transaction. Agent transactions are serialized per document and scheduled round-robin across at most four visible lanes when an editor is attached. With no renderer, the same validated transactions commit immediately instead of sleeping for invisible animation. A session may queue four transactions, a request may contain 256 operations/2 MiB, and visible work shares a one-million-sample budget. Compact row runs are charged by addressed cells rather than run count. Unrelated operations proceed; stale/conflicting operations return retry guidance and coarse human occupancy.

Autonomous work larger than one transaction can use a durable numbered batch. Its atomically replaced ledger contains only a hashed resume token, document/sequence/progress, and committed transaction IDs; canonical drawing data remains in the ordinary journal and trace. Startup reconciles the narrow crash window between a successful reducer commit and progress persistence from that durable trace, while an opaque token allows ownership to rebind to a new authenticated MCP session.

Cancelling an active lane slices strokes/pixel changes at the current reveal position, commits that prefix with `partial` activity, and drops the rest. The prefix remains one attributed undoable transaction. Human and each MCP actor have independent undo/redo stacks.

## Rendering and storage

Illustration documents retain one bounded artboard, editable scene objects, paint strokes, and schema-2 object-pose animation keyframes. Timeline evaluation is deterministic across UI, headless observation, and GIF/APNG export: transform values interpolate under linear/hold/ease-in-out policy while opacity/visibility remain canonical tracks. Revision-checked artboard translate/expand is one canonical transaction that moves root objects, paint samples, guides, and root-object keyframes together; generation acceptance uses it for undoable outpaint. Canvas renderers produce the interactive view and export composite; paint strokes are also materialized into sparse, content-addressed 256×256 PNG tiles when saving and decoded through a bounded recent-tile LRU. Pixel cels use base64-packed 32×32 indexed chunks; infinite maps use base64-packed 32×32 `uint32` GID chunks with Tiled transform flags. Canonical pixel/tile region operations write compressed row runs directly across chunk boundaries and retain exact inverse runs for undo.

Pixel-project links keep a portable relative path, a content hash, and an embedded cached source. Human Embed, Extract, Relink, and Pack actions never enumerate the filesystem: native dialogs provide exact paths, extraction uses guarded atomic writes, replacement assets cross the inline-raster trust boundary, stale caches fail closed, and whole-link-list replacement carries the document revision so a long-open dialog cannot overwrite concurrent agent work. Headless MCP clients use the same kernels through semantic embed/pack operations and approval-backed relink/extract file requests.

The v1 renderer boundary is intentionally application-owned Canvas2D rather than third-party scene serialization. The renderer and headless export paths consume the same model/geometry/brush kernels; Paper.js is isolated to exact path geometry and `perfect-freehand` to pressure outlines. Unused Fabric.js, PixiJS, and tilemap runtime dependencies were removed once deterministic cross-mode goldens and the vector/4K-paint/large-map performance gate existed. This avoids maintaining two authoritative scene graphs; packaged frame-pacing evidence is still required before release.

`.aidraw` is a schema-versioned ZIP (currently manifest/document schema 2) with `manifest.json`, `document.json`, `activity.json`, `trace/transactions.jsonl`, `preview.png`, and `assets/<sha256>`. A temporary archive is closed, reopened, migrated, and validated before atomic replacement. Native reads reject unsafe entry paths plus per-entry, count, compressed, and expanded-size excess before extraction; schema-1 containers migrate through fixtures. Recovery journals append committed transactions and compact to a snapshot every 60 seconds; shutdown waits for pending journal replacement so Windows cleanup cannot race an unobserved rename. The separate per-document trace store is append-only and is never erased by recovery compaction; save/open round-trips it with the native file. Activity or an authorized MCP session can replay one bounded traced transaction as a non-mutating canvas overlay.

`canvas_observe` can render a validated asset/frame/layer/region or exact illustration timeline time with integer nearest-neighbor scale and explicit background. Pixel count is checked before raster allocation and encoded PNG size is capped. Each open document retains only the immutable pre-transaction snapshot for its most recent commit, enabling a revision-labelled before/after observation pair without an unbounded snapshot history; the pair shares one pixel budget. Renderer-only collaboration state crosses a separate advisory IPC path: while an editor is attached it publishes document/tool/selection/zoom, visible viewport, and animation hints, and clears them on detach. Advisory state never mutates the canonical workspace or feeds back into workspace publication.

CPU-heavy and untrusted raster/provider work runs behind supervised Electron utility processes. Quantization, addressed import/conversion, document export, MCP observation compositing, generation comparison rendering, provider network/workflow execution, generated-preview acceptance normalization, and accepted pixel-result quantization each use typed requests. A worker handles one task at a time, rejects the active task on crash, and restarts fresh for queued work. Each independent supervisor retains at most 32 waiting requests; the next call gets explicit retryable backpressure, and queued cancellation frees capacity without changing FIFO order. Quantization enforces its source-byte boundary before base64 amplification and validates the child result against the originating width×height and palette before caller or canonical use: result count, integer coordinates, coordinate uniqueness, bounds, palette indexes, kind, and response/error envelopes all fail closed, retire the worker, and let queued work restart fresh. Document export likewise validates the serialized primary artifact and every companion before permissive base64 decoding: canonical base64 syntax, MIME/extension strings, safe companion leaf names, and string-only report arrays fail closed and replace the worker. Existing per-format geometry limits do not define one total encoded-byte ceiling across compressed raster, vector, container, animation, and companion output, so no global export-result cap is implied or claimed. Import results must contain 1–256 documents—the existing PDF page ceiling and current sole multi-document path—plus string-only warnings; every returned document passes through the established migration/schema gate before caller or workspace use, and any failure retires the worker. No common serialized-document or warning-size budget is implied by the existing per-format input and expansion limits. Observation results now accept only the established error discriminants or an exact request-derived success: target/region/scale dimensions and `maxPixels` must agree, data must be canonical base64 within the existing 4 MiB static-PNG ceiling, and the bounded PNG container, chunk CRCs, IHDR dimensions, image-data/end markers, and non-APNG identity must agree before the existing static-PNG codec produces exactly one matching width×height RGBA plane for caller/MCP use. Generation results likewise cannot exceed the originating result count and require unique IDs, the exact PNG/JPEG/WebP MIME/header/dimension contract, canonical base64, the existing per-image 32 MiB / 8,192-side / 32 MP producer limits, request-consistent seed attribution, and record-shaped provider metadata before preview/job use. Canonical provider/model/prompt provenance continues to come from the main-owned request rather than provider metadata. Generation progress is advisory: only a matching active generation request with finite 0–1 progress and a string message is relayed; malformed or cross-lane telemetry stays invisible without aborting the provider task, while terminal response, timeout, and cancellation remain authoritative. These gates are not generic result-size, progress-message-size, or RSS policies. At explicit human acceptance, a valid preview above the 1.5 MB inline/quantizer ceiling is normalized in the raster lane without resizing: lossless PNG re-encoding is tried first, then the first fitting quality from one fixed descending alpha-preserving WebP ladder. The accepted derivative must pass the exact inline-asset contract before quantization or commit; source and accepted hashes/bytes/codecs are recorded while the original provider output stays unchanged in the private job. If same-geometry output cannot meet the established byte or geometry contract, the result stays preview-only with guidance and no canonical mutation. Raster cancellation/timeouts replace the worker immediately; generation cancellation first signals its AbortController and allows bounded provider cleanup—such as ComfyUI queue removal/interrupt—before force replacement. Generation uses a separate lane so a long provider request cannot block drawing observation/export. The utility bundle is a required package artifact; exact Windows crash/cancel, queue/input-pressure, quantization-result, observation-codec, generated-preview acceptance-normalization, fixed sprite-sheet PNG+JSON export-result, and import-result scenarios pass. A fixed provider-free general-generation result observer now has exact package/static/list acceptance against one immutable Windows package and a separately frozen unexecuted graceful-only runtime guard; native behavior, exact RSS, and broader platforms remain release gaps.

Generation requests are capability-checked before approval and again before dispatch. They never silently change providers or automatically retry an ambiguous potentially paid POST. OpenAI outpaint is a real edit request: AIDraw pads the source into the requested output canvas and supplies a same-size alpha mask that exposes only the expanded region.

Interchange is explicitly hybrid rather than pretending at lossless foreign serialization. SVG maps supported groups, transforms, styles, gradients, clips, blur, images, ranged text, and primitives into the native model. PSD retains supported group and text structure beside visible raster fallbacks and a composite. PDF export keeps supported simple paths/shapes, standard-font text, and images native while transparently rasterizing unsupported effect groups; PDF import retains page appearance and extracted text but does not yet translate general content-stream operators. Every adapter records its fallbacks and warnings.

## Security boundary

BrowserWindow uses sandboxing, context isolation, no Node integration, no webviews, denied permissions/navigation, CSP, and hardened Electron fuses. Production renderer assets are served only from the restricted `aidraw://app` protocol, with `file://` extra privileges disabled. IPC validates the exact sender/main frame. Hosted keys and the MCP token use Electron `safeStorage`: DPAPI on Windows, Keychain on macOS, and a supported system secret store on Linux. AIDraw refuses Linux `basic_text`. Credentials remain main-owned and are passed only in the typed request for the isolated provider worker; they are never exposed to MCP responses and are revealed to the renderer only for the explicit connection-settings action.

MCP uses authenticated stateful Streamable HTTP on a persistent first-available port from 48200–48231. Model mutations are safe to perform headlessly. Files are accessed only by explicit canonical paths; session/persistent folder trust can skip repeated non-overwriting prompts. Every overwrite and every agent generation still requires prior authority, and such jobs remain pending until an editor attaches rather than weakening the boundary in headless mode.

The commit boundary replaces client-proposed entity revisions, creator IDs, and timestamps with authenticated actor/commit values, recursively including sprite layers, frames, and cels. Optional model/reasoning/task metadata is validated and persisted as client-declared attribution, not platform attestation. Undo/redo operates on the resulting trusted inverse so exact restoration is preserved. Generic canvas transactions cannot add or remove verified generation provenance. Embedded-asset deletion is rejected while image objects, paint tiles, linked previews, or provenance still reference it; an explicit ordered cascade remains possible and exactly invertible. Job enumeration is owner-scoped and sanitized before crossing MCP so result payloads and human approval details do not leak between sessions.

Inline assets do not grant filesystem authority, but they are still untrusted input. Only canonical base64 raster PNG/APNG/JPEG/WebP/GIF payloads are accepted, with a 1.5 MB decoded limit, SHA-256/length/MIME checks, safe header dimensions, an 8192 px side/16 MP limit, and a real codec decode before commit. Agent claims of a generated source are normalized to ordinary embedded data; verified generation status comes only from the engine-owned provenance path.

Addressed imports are likewise untrusted after file approval. Root files have format-specific byte caps; raster/PSD/PDF headers and decoded surfaces, animation frames, sprite-sheet expansion, Tiled layers/chunks/objects/tiles, and compressed layer output have explicit budgets. SVG/TMX/TSX reject DTD/entity declarations. Metadata, external tilesets, and source images may follow only realpath-resolved relative references contained within the approved root folder, preventing `..` and junction/symlink escapes without granting file enumeration.

The product remains a local desktop engine/editor with concurrent localhost MCP sessions. Windows is the currently packaged and exercised baseline. macOS/Linux runtime abstractions, secure-storage policy, login behavior, Forge makers, and native CI jobs are implemented, but they are not promoted to verified release targets until native jobs and Computer Use acceptance pass. Remote service tenancy, accounts/cloud sync/remote multiplayer, mobile, and web remain separate programs.
