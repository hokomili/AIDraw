# Architecture

## Process ownership

`EngineRuntime` is the canonical, BrowserWindow-independent owner of open documents, active-document identity, the transaction reducer, per-actor histories, locks, jobs, persistence, recovery, durable traces, credentials, supervised utility workers, and the localhost MCP endpoint. It runs in the Electron browser process but does not require a renderer. The React editor is an attachable client that receives immutable, monotonically ordered workspace snapshots through a narrow preload facade and keeps only optimistic pointer previews and UI state. It subscribes before bootstrap hydration and rejects an older reply/event, so an asynchronous tab response cannot replace newer canonical state. It cannot access Node or Electron directly.

The first process for a user profile takes Electron's single-instance lock. `<AIDraw executable> --headless` starts only `EngineRuntime`; a later ordinary launch signals that owner to create or focus an editor window. Closing the last window disables visual-delay scheduling but deliberately leaves the process and MCP engine alive. **File → Quit AIDraw Engine** or `--quit-engine` is the explicit full shutdown. Guided client setup registers headless startup through Windows login items, macOS login-item launch detection, or an XDG autostart entry on Linux.

Application settings and diagnostics that do not belong inside artwork use bounded atomic stores under the engine user-data directory. Reusable document presets retain strict `NewDocumentOptions` values without document names. Interchange diagnostics retain the latest 200 actor-attributed import/export outcomes, exact addressed paths, adapter warnings, and raster fallbacks, and can be exported as standalone JSON without modifying a drawing. A renderer recovery boundary can also write one user-addressed, bounded local diagnostic with runtime and sanitized tab/job/MCP summaries; it deliberately omits document content, assets, prompts/results, task IDs, tokens, and credentials.

All committed changes are `CanvasTransaction` values over the application-owned model in `packages/core`. Every canonical operation kind has a bounded runtime payload schema. The reducer verifies document identity and expected entity revisions, produces inverse operations, increments revisions, and records attribution. Layer/object replacements may change entity content but not ordered layer, vector-layer, or object-group membership; those structural edits must use the dedicated add/move/delete operations so their exact positions remain invertible. File formats and renderer libraries are adapters; their private serialization never becomes the native model.

## Concurrency

Pixel fill and replacement are one-shot previews. Pointer cancellation or Escape synchronously clears every transient gesture state, then best-effort releases each distinct lock that eventually resolves, and never invokes the commit path.

Human gestures preview in the renderer and acquire object or pixel/tile-region locks from pointer-down through commit. Multi-object translate/scale/rotate holds one object-set lock and commits revision-checked replacements as one human transaction. Agent transactions are serialized per document and scheduled round-robin across at most four visible lanes when an editor is attached. With no renderer, the same validated transactions commit immediately instead of sleeping for invisible animation. A session may queue four transactions, a request may contain 256 operations/2 MiB, and visible work shares a one-million-sample budget. Schema-shaped but non-JSON-serializable transactions return a canonical conflict before size accounting or mutation. Compact row runs are charged by addressed cells rather than run count. Unrelated operations proceed; stale/conflicting operations return retry guidance and coarse human occupancy.

Autonomous work larger than one transaction can use a durable numbered batch. Its atomically replaced ledger contains only a hashed resume token, document/sequence/progress, and committed transaction IDs; canonical drawing data remains in the ordinary journal and trace. Startup reconciles the narrow crash window between a successful reducer commit and progress persistence from that durable trace, while an opaque token allows ownership to rebind to a new authenticated MCP session.

Cancelling an active lane slices strokes/pixel changes at the current reveal position, commits that prefix with `partial` activity, and drops the rest. The prefix remains one attributed undoable transaction. Human and each MCP actor have independent in-memory undo/redo stacks; recovery deliberately starts new stacks rather than presenting a partial persistent history.

Each history entry retains the logical targets of both its committed transaction and generated inverse. Monotonic expected revisions are rebound only when that actor invokes the current top entry and no later foreign transaction touched an overlapping target. Disjoint object/cel/layer histories remain independently undoable; a foreign overlap permanently blocks crossing that entry, and an explicitly unrecorded same-actor mutation creates the same barrier. A newer own edit made after foreign work can undo back to that foreign state but cannot cross it. Whole pixel-asset targets contain nested frame/cel/layer targets, while document-revision-guarded operations remain blocked by every foreign commit because their concurrency token is intentionally global. The snapshot disables undo/redo when its top entry is blocked, and direct callers receive the attributed conflict. Undo and redo commits are journaled, traced, and included in revision-based change observation. Blindly rebasing every inverse was rejected because it could overwrite another actor's work; automatic semantic merging or CRDT history is not claimed.

## Rendering and storage

Shared pixel-tool kernels cache indexed chunks, preserve ordered pencil revisits, rasterize symmetric integer ellipses, and return flood/replacement regions as canonical row runs. Floods cap the actual connected result at one million cells; replacements cap the inspected target at one million cells; both cap output at 65,536 runs and return no partial result. The interactive surface intentionally reads the visible composite for fill, wand, and replacement while semantic operations read their addressed cel. Sprite/tile selections and reusable pixel/tile stamps expose separate clockwise and counterclockwise quarter-turn actions, but both directions use the same exact indexed/GID kernels as semantic execution; no renderer-local rotation path or direction toggle owns different geometry.

Tileset geometry is edited as a draft rather than committed field-by-field. A bounded nearest-neighbor first-frame thumbnail overlays the current grid, proposed grid, and selected source rectangle without allocating the source-sized bitmap. Re-slicing uses one immutable graph-aware kernel: the default source-position policy follows exact cell origins, while the explicit tile-ID policy preserves ordinal Tiled IDs; both remap animation targets, Wang representative tiles, and Wang assignments together. Ambiguous source-origin collisions fail closed, references that no longer fit are removed rather than redirected to invented representatives, and an exact impact summary plus acknowledgment precedes any metadata reframe, renumber, or loss. The accepted result remains one revision-checked asset replacement and stores blank cells sparsely, including at the established 1,048,576-tile ceiling.

Non-Wang random variants use the tile's nonnegative probability plus the AIDraw-namespaced `aidraw:variantGroup` custom property. UI and semantic MCP selection hash the selected tile ID, signed persisted `aidraw:variantSeed`, and exact map coordinate, so one seed is replayable without ambient randomness. The editor shows at most twelve 32-pixel crop thumbnails and advances the signed seed through one deterministic successor when the user requests a new stroke; that revision-checked property edit never retroactively rewrites painted GIDs. Both properties serialize as ordinary typed Tiled custom properties, not a claim that Tiled implements AIDraw's selection convention.

Tileset animation metadata is an ordered list of tile IDs and positive millisecond durations. The selected-tile editor changes that canonical order through one immutable move kernel, whether initiated by drag-and-drop or keyboard controls, and commits the resulting tileset as one revision-checked asset replacement. Its visual preview follows Tiled tileset semantics rather than the source sprite's own frame timeline: it composites the source sprite's first frame, crops only the addressed tile rectangle through the same layered pixel compositor used by the map canvas, and advances by authored durations. The preview is explicitly pausable and starts paused for reduced-motion users. Tiled JSON/XML writers serialize list order unchanged.

Tileset collision multi-selection is editor state rather than a format extension. Checkboxes, Select all/Clear, and Shift-click produce an explicit set of existing shape IDs; a group drag applies the same rounded integer translation to every member, keeps canonical collision order and each shape's local geometry/properties exact, then merges the changed records through one human lock and one revision-checked tileset replacement. Handles and property editing remain single-selection operations because no group scaling or property-merge contract has been established. The collision canvas samples the source sprite's first-frame tile crop directly into at most 240×200 CSS pixels; valid maximum tile geometry therefore does not imply a source-sized preview canvas or per-source-pixel loop.

Sparse tilemap chunk insertion order is never visual z-order. Isometric tile layers in both renderer and headless export traverse the existing right-down convention by sorted chunk-Y bands, sorted chunk X within each band, and complete global rows before later rows. One shared generator decodes only the active chunk band and yields nonzero cells lazily, avoiding a complete cell-object array at the 16-million-cell import ceiling; orthogonal maps retain their existing streaming path. A separate pure projection kernel defines the finite `(columns + rows)` extent, row-derived horizontal origin, authored tile aspect ratio, cell rectangles, continuous inverse, screen-delta inverse, and map-object affine matrix. Headless and interactive artwork plus interactive object, pointer, parallax, selection, lasso, stamp/tool, and replay feedback consume that geometry, so rectangular maps neither center by the wrong axis nor lose the former half-cell edge. These changes affect no chunk storage or Tiled output and retain exact unsigned GIDs/transforms. Reverse-inserted row-31/32 overlap and an edge-to-edge 4×2 one-cell tile are the deterministic render regressions. Native tileset-height overhang, tile offsets/alignment, non-square transformed-tile geometry, infinite-view expansion beyond nominal bounds, and packaged visuals remain separate gaps.

Orthogonal map cells likewise retain the canonical `tileWidth:tileHeight` aspect instead of becoming square in the editor. One pure extent/cell/inverse/delta/object-matrix contract is shared with headless rendering. The editor treats its horizontal fit scale as `tileWidth` and derives row height from `tileHeight / tileWidth`; tile artwork, object overlays and hit testing, CSS-scaled pointer input, parallax correction, grid rows, selection/lasso/stamp/tool/replay feedback, and canonical raster dimensions therefore agree. Applying one uniform screen scale to canonical object pixels was chosen over independent X/Y distortion. This is cell-projection parity only: tileset images still scale into their addressed map cell, and native-size overhang, explicit Tiled tile offsets/alignment, non-square diagonal-transform policy, infinite-view expansion, and packaged visual acceptance remain separate decisions.

Map-object layers are canonical visible layers, not editor-private decoration. One shared overlay renderer owns rectangle, ellipse, polygon, and polyline paths plus AIDraw's fill/stroke and selected-handle appearance. The editor supplies advisory selection and viewport parallax; headless observation/raster export supplies no selection and uses canonical pan zero, so parallax contributes no displacement. Both surfaces honor nested flattened z-order, visibility, and multiplied layer opacity and use the same orientation-specific projection matrix. Lock state constrains editing rather than visibility. Tiled interchange continues to serialize object metadata rather than AIDraw overlay pixels, so this parity does not claim a Tiled-native style convention.

Sprite cel exposure remains the canonical layer×frame relation already stored by one raw cel per pixel-layer/frame pair. The editor pages this relation at twelve frames by six pixel layers, labels independent/linked/missing state, and selects both coordinates explicitly. Per-exposure link follows the previous frame's resolved cel and clears that exposure's own chunks; unlink snapshots the currently resolved chunks. Both are immutable whole-sprite derivations committed through the established revision-checked asset replacement, so no parallel cel mutation language is introduced. Pixel tools honor the selected pixel layer when it is visible and unlocked; an explicitly selected hidden or locked layer resolves to no editable target rather than falling through to another layer. This preserves layer intent across drawing, fill, selection, text, and paste.

Onion-skin configuration is advisory renderer session state rather than artwork. A shared planner validates independent previous/next counts from zero through four, base opacity from zero through one, and six-digit RGB tints, then returns at most eight neighboring frames in global far-to-near order with each side attenuated by base opacity divided by distance. Defaults preserve the existing one-previous teal 22% and one-next pink 18% preview. The settings panel never submits a canonical operation, opening it does not silently enable the separate Onion toggle, and it is mutually exclusive with the cel-exposure overlay. Persisting visual-aid preferences into `.aidraw`, exports, or MCP was rejected without a separate product need; unbounded frame fan-out and a second rendering convention were rejected for predictability and cost.

Reusable stamp transfer is a strict application-owned JSON interchange boundary, separate from native `.aidraw` persistence. A pure parser validates the versioned envelope through the canonical palette/stamp operation schemas, caps serialized input at 16 MiB and aggregate cells at 262,144, and preserves the established 1,024-stamp/65,536-cell-per-stamp limits. Pixel import maps referenced nontransparent colors by exact case-insensitive value, appends exact missing colors with fresh IDs up to 256, and fails rather than approximating a color. Tile export records only tilesets addressed by nonzero stamp GIDs; import requires the active map to expose the same tileset name, identity, revision, GID range, geometry, and source-sprite identity/revision/size, then retains all unsigned transform flags unchanged. It does not bundle pixels or infer GID rebasing. The dialog defaults to append with fresh stamp IDs and collision-free names, makes replace explicit, and does not submit canonical operations until a parsed import plan has been previewed and revalidated for one transaction. A document-revision change expires that preview and requires review again. File loading receives one user-selected file and grants no path or enumeration authority.

Illustration documents retain one bounded artboard, editable scene objects, paint strokes, and schema-2 object-pose animation keyframes. Timeline evaluation is deterministic across UI, headless observation, and GIF/APNG export: transform values interpolate under linear/hold/ease-in-out policy while opacity/visibility remain canonical tracks. Revision-checked artboard translate/expand is one canonical transaction that moves root objects, paint samples, guides, and root-object keyframes together; generation acceptance uses it for undoable outpaint. Canvas renderers produce the interactive view and export composite; paint strokes are also materialized into sparse, content-addressed 256×256 PNG tiles when saving and decoded through a bounded recent-tile LRU. A save reuses an exact validated stroke-prefix cache, rerenders only tile keys touched by appended strokes, and adopts the derived cache into the live document only after durable atomic replacement; failed saves leave the prior live cache unchanged. Native open rejects incomplete tile coverage as well as invalid prefix, bounds, payload, or hash metadata. Pixel cels use base64-packed 32×32 indexed chunks; every canonical cel byte and reusable-stamp cell must name a current palette slot, and each frame override must preserve the current palette's length and entry-ID order. Infinite maps use base64-packed 32×32 `uint32` GID chunks with Tiled transform flags. One core affine kernel defines their anti-diagonal-first, then horizontal/vertical order for both interactive and headless/export Canvas2D consumers, preventing renderer drift. Placed-tile animation first resolves the authored local frame tile through an exact looping millisecond sampler and then applies that stored transform. The editor shares one session-local phase across the map, clamps scheduling to at least 16 ms, and freezes at time zero for reduced motion; headless observation and static raster export also use time zero so identical canonical input cannot vary with wall-clock time. Both map renderers then composite only the smallest integer source envelope intersecting the addressed tile while retaining the original fractional sample rectangle and nominal sprite clipping. Repeated crops use a per-render 64 MiB / 1,024-entry disposable LRU; over-budget single crops are transient, and every retained native/browser canvas is released after the render. This keeps a small addressed crop independent of an otherwise maximum-size sparse sheet without pretending a maximum-size tile itself is cheap. The source sprite's independent frame timeline is not substituted for tileset animation, and no canonical GID is rewritten. Canonical pixel/tile region operations write compressed row runs directly across chunk boundaries, retain exact inverse runs for undo, and remove a chunk again when its decoded contents return entirely to zero so undo restores sparse absence rather than a dense zero allocation.

The square-tile transform chooser enumerates the same eight raw GID-flag states without adding another transform representation. Each preview renders only the selected source crop into one 32×32 scratch canvas, applies the shared core matrix about its center, and releases that scratch surface to 1×1 after use. Tileset `hFlip`, `vFlip`, and `rotate` are geometric capabilities rather than independent bit permissions: quarter turns require diagonal-plus-flip encodings, a half turn uses both flip bits, and one reflection combined with rotation generates the full square symmetry group. A pure permission kernel therefore retains an exact allowed flag state or returns identity; it never strips individual bits into a different transform. The picker and quick toggles share that kernel, while existing painted GIDs and document/interchange state remain untouched. A separate rectangular diagonal cell-fitting policy is still required before the bounded preview is shown for nonsquare tiles.

Interactive illustration click selection uses one synchronous Canvas path kernel because pointer-down must be able to begin a move/gradient/crop lock without waiting for the lazily loaded lasso engine. The kernel shares the renderer's local shape, pressure-outline, arrowhead, and affine inverse geometry. It checks stored fill rules, configured stroke cap/join/dash, and an object/view-scale-adjusted eight-pixel boundary affordance while saving/restoring Canvas state. A supported painted miss is final; falling through to expanded bounds was rejected because it selected empty corners and holes. Bounds remain intentional only when geometry is unsupported, malformed, non-invertible, paintless, or the Canvas context is unavailable. Topmost order and Alt cycling remain renderer selection state. This does not aggregate group children, masks, filters, shadows, blur, or claim an exact Euclidean screen-distance envelope under nonuniform skew.

Shape and editable-path stroking shares one DOM-neutral Canvas state applicator across the renderer and headless raster path. It assigns canonical width/cap/join/dash, pins the Canvas default miter limit to 10, and multiplies the saved context's existing alpha by canonical stroke opacity. Paint resolution remains renderer-local so gradients retain their established context, and each object remains inside saved/restored state. The click kernel uses the same explicit miter limit for configured stroke geometry without applying visual opacity. A zero-width or nonpainted stroke is not issued. Duplicating incomplete field subsets was rejected because editor, observation, static raster output, and SVG/PDF export had drifted despite already sharing one `StrokeStyle` model; no new schema or custom-miter field is introduced.

Path booleans remain one DOM-neutral Paper.js kernel used before either the editor or MCP builds its atomic delete/delete/add transaction. Canonical `evenodd`/`nonzero` rules are assigned to path inputs before their existing transforms are flattened, and the returned compound path stores Paper.js's result rule rather than relabeling every result `nonzero`. An empty Paper result cannot satisfy the canonical nonempty `pathData` schema, so the kernel rejects before callers submit any deletion; a placeholder object or implicit deletion was rejected. The established first-input layer, opacity/blend, fill, and stroke policy remains, but style values are cloned so the new object shares no mutable recipe arrays with its source. A `finally` boundary removes the temporary Paper project on every success or failure. This does not define compound-hole node editing, general multi-subpath authoring, style blending, utility-process isolation, or foreign-format mapping.

Freeform illustration lasso selection lazily loads one Paper.js geometry kernel after a gesture completes; it does not create another scene graph or mutate the document. One affine matrix matching Canvas2D transforms canonical fill silhouettes, `perfect-freehand` pressure outlines, text/image frames, and stroke-only centerlines into world space. Fill intersection uses exact path booleans and honors the stored fill rule; centerline containment splits at exact curve/polygon intersections and checks every resulting interval. Selection order and replace/add/subtract/intersect semantics remain renderer state. Core geometry was chosen over rotated bounds because bounds create both corner false positives and curved-containment false negatives; raster sampling was rejected because it would make selection depend on zoom, device pixels, and antialiasing. Unsupported groups or malformed paths retain the prior bounds fallback. Stroke envelopes, masks, clipping, blur, shadows, filters, and selection handles are deliberately not redefined by this checkpoint, and packaged pointer behavior remains separate evidence. The formal source gate now budgets a 5,000-object lasso at 1,000 ms.

Illustration image crops retain source-space rectangles on the existing image object. Canvas gestures continue to derive that rectangle from display-space geometry; numeric inspector fields instead accept source-pixel X/Y/width/height because source geometry is durable across object transforms and interchange. One pure kernel validates finite positive in-bounds geometry, preserves fractional values, derives the current display-units-per-source-pixel ratio from the active crop, and moves the local origin through the same scale/skew/rotation matrix used by both renderers before replacing width, height, and crop together. The exact full-source rectangle routes through the established crop reset. Apply submits one ordinary revision-checked object replacement; no asset bytes, IDs, schema, relink policy, or export contract change. A full transform reset is deliberately separate: resetting to identity at the origin, preserving position, and baking geometry are different user-visible outcomes and no authority has selected one.

Custom raster-brush interchange is a renderer-owned, versioned JSON boundary over the existing canonical preset array. One pure parser/planner reuses the live `illustration.brush-presets.replace` schema, rejects unknown fields and built-in reserved IDs, and enforces 1 MiB/256-preset limits before producing a single replacement operation. Append mode allocates fresh non-built-in IDs and case-insensitively unique custom names; explicit replace preserves imported IDs and touches only the custom library. The dialog reparses after a revision-bound preview before submitting the ordinary transaction, then selects the committed recipe values directly from that operation. Existing strokes remain self-contained because their recipe and seed are embedded. This adds no `.aidraw` field, global store, directory authority, built-in/stroke/tip-image transport, tags/folders, or third-party brush contract.

Pixel-project links keep a portable relative path, a content hash, and an embedded cached source. Human Embed, Extract, Relink, and Pack actions never enumerate the filesystem: native dialogs provide exact paths, extraction uses guarded atomic writes, replacement assets cross the inline-raster trust boundary, stale caches fail closed, and whole-link-list replacement carries the document revision so a long-open dialog cannot overwrite concurrent agent work. Headless MCP clients use the same kernels through semantic embed/pack operations and approval-backed relink/extract file requests.

The v1 renderer boundary is intentionally application-owned Canvas2D rather than third-party scene serialization. The renderer and headless export paths consume the same model/geometry/brush kernels; Paper.js is isolated to exact path geometry and `perfect-freehand` to pressure outlines. Unused Fabric.js, PixiJS, and tilemap runtime dependencies were removed once deterministic cross-mode goldens and the vector/4K-paint/large-map performance gate existed. This avoids maintaining two authoritative scene graphs; packaged frame-pacing evidence is still required before release.

`.aidraw` is a schema-versioned ZIP (currently manifest/document schema 2) with `manifest.json`, `document.json`, `activity.json`, `trace/transactions.jsonl`, `checkpoints/index.json`, `checkpoints/<id>.json`, `preview.png`, and `assets/<sha256>`. A temporary archive is closed, reopened, migrated, and validated before atomic replacement. Native reads reject unsafe entry paths plus per-entry, count, compressed, and expanded-size excess before extraction; the manifest is validated as an integrity summary and its schema, document identity/kind/name, revision, timestamps, and generic asset count must exactly match `document.json`. Native asset metadata must match the writer contract; inline document bytes are discarded, and content-addressed entries hydrate only after exact length and SHA-256 verification. Generic image payloads must additionally agree with their claimed PNG/APNG/JPEG/WebP/GIF MIME, bounded display geometry, and a supervised real codec decode. Missing, corrupt, or undecodable payloads retain metadata but omit data with the established warning; malformed metadata and contradictory identity remain fatal. The writer rejects supplied non-canonical, hash/length/MIME/header/geometry/decoder-contradictory bytes before lazily rendering the preview, opening a temporary, or replacing the destination, while deliberately absent payload metadata remains recoverable. A canonical document whose nominal static raster exceeds 65,535 pixels per side or 64 megapixels remains saveable: the auxiliary preview uses the established transparent 1×1 fallback instead of allocating or redefining the document. Matched schema-1 containers migrate through fixtures. Selected checkpoint summaries and payloads independently require exact writer metadata and must agree with one another plus the migrated checkpoint document's identity/revision; duplicate IDs and malformed entries stay isolated from the main document, while save rejects invalid or inconsistent checkpoint input before replacement. The stored-name contract remains nonblank rather than adopting the manual-entry length cap so restore-authored safety names remain compatible. Recovery journals append committed transactions and compact to a snapshot every 60 seconds. A separately replaced workspace manifest preserves exact tab order and canonical active-document ID, while every document snapshot preserves its own real dirty bit and file association; recovery never infers that all open documents are dirty. Graceful shutdown first stops new MCP work and utility lanes, then writes the final document and workspace snapshots and waits for pending replacement so cleanup cannot race an unobserved rename. The separate per-document trace store is append-only and is never erased by recovery compaction; save/open round-trips it with the native file. Native and local trace ingestion share the exact version-1 writer envelope, canonical metadata, same-document canonical transaction schema, and existing 2 MiB transaction ceiling; malformed records are excluded before inspection/replay, native warnings are aggregated, valid history remains untruncated, and import uses one batched append. Activity or an authorized MCP session can replay one bounded traced transaction as a non-mutating canvas overlay.

`migrateDocument` is also the shared attribution boundary for native open, recovery snapshots, and utility-imported documents. Persisted activity entries must match the exact record envelope and schema-valid actor/status/count contract, while provenance entries reuse the strict live-operation provider/model/prompt/source/mask/conversion schema; each sequence requires unique entry IDs. This prevents malformed attribution from reaching agent activity accounting or renderer controls and malformed provenance from reaching asset-reference traversal. Missing referenced assets retain the established partial-recovery behavior, and structurally valid file-authored attribution is not authenticated. `activity.json` remains a writer mirror; `document.json` is canonical.

That same migration boundary now reuses the live-operation schemas for the complete persisted illustration field family: artboard, root order, group/vector/paint layers and strokes, vector-stroke/path/shape/text/image/group objects, brush presets, guides, snap settings, and animation. Exact nested envelopes, finite bounds, unique ordering/membership IDs, and record-key/entity-ID agreement are enforced before renderer/export consumers. This remains structural validation rather than graph completion: a missing referenced layer/object/mask/asset or a valid unreferenced record retains the existing partial-recovery behavior, while a malformed field or contradictory record identity rejects the canonical document. Existing schema migration and absent-preference defaults remain intact.

Pixel migration has an explicit two-stage boundary because older and agent-authored pixel records intentionally support bounded recovery. The normalizer first supplies missing frame/cel entity metadata, empty chunks and absent reusable-library/link/conversion preferences, rekeys recoverable record aliases, drops records that cannot identify a sprite exposure, and retains unavailable cross-record targets. A second shared schema boundary then proves the returned palette/libraries, sprite/frame/cel/chunk, tileset/tile/collision/Wang, tilemap/layer/object/chunk, link, and conversion state exact enough for canonical renderer/export use. Duplicate raw entity identities reject before normalization can overwrite content. New pixel-asset and library operations use the same nested schemas, with their stronger live-reference requirements. After shape validation, canonical sprite-cel bytes and reusable-stamp indices must be below the current palette length; frame overrides must have that exact length and preserve entry IDs in order. This is deliberate normalization followed by validation, not arbitrary repair or full graph reconciliation.

Recovery journal filenames are SHA-256 derivations of opaque document IDs rather than the IDs themselves, preventing imported traversal and case-fold collisions. Safe legacy direct-child names remain readable and migrate only after a successful hashed compaction. One migrated snapshot is replayed through a contiguous sequence of same-document canonical transactions; a torn, malformed, cross-document, or non-applicable record is a barrier, so recovery keeps prior committed work without jumping to later edits. Native open queues its first snapshot before any immediate transaction append. The workspace index is advisory ordering state and is admitted only under its exact unique-ID/active-membership writer shape; rejecting it never rejects valid document journals. This is application-level atomic replacement and replay integrity, not a filesystem-fsync or power-loss guarantee.

`canvas_observe` can render a validated asset/frame/layer/region or exact illustration timeline time with integer nearest-neighbor scale and explicit background. Pixel count and the 65,535-pixel per-side ceiling are checked before source or output raster allocation, and encoded PNG size is capped. Tilemaps use a nominal-region renderer instead of constructing the full nominal map first; a four-pixel allocation-aware backing margin preserves the current object-overlay antialiasing before an exact raw-pixel crop. Before any 32×32 GID payload decode, a pure filter intersects the chunk's conservative projected cell envelope with that backing region. The envelope covers both projections and pads by the larger tile axis so any stored rectangular-cell transform remains a candidate; retained record order is unchanged before isometric right-down ordering. The editor shares that filter: it inverts its uniform projected view plus each layer's parallax translation, rounds fractional viewport edges outward in canonical map pixels, and bounds orthogonal grid-line indexes with one neighboring line for clipped stroke coverage. Map-object rendering expands each canonical object AABB by the explicit Canvas miter limit and any selected handle extent, transforms four corners through the exact orientation matrix, and retains intersecting objects in source order; editor matrices include layer parallax and preview geometry, while headless matrices use canonical pan zero. Sprite base/onion/wrap rendering uses the same generic viewport inversion and the established shared region compositor; exact option hooks retain linked-cel resolution, nested opacity/blend, frame palettes, cycling/tint, and replay masks, while a wrap copy subtracts its canonical sprite offset before candidate lookup. Sparse paths and object layers still inspect stored metadata linearly: they remove irrelevant decode/cell/path work but are not spatial indexes. Requested MCP map regions remain nonnegative and contained by the nominal projected rectangle; the editor's viewport region may extend beyond it and only affects transient clipping work. Whole-raster PNG/JPEG/WebP/pixel-SVG/pixel-PDF export checks the same 65,535-side and 64-megapixel safety boundaries before rendering, and never silently downscales. These are allocation/traversal contracts, not a stored-chunk bounds/origin change; signed chunks can remain outside nominal bounds under the unresolved infinite-view policy. Each open document retains only the immutable pre-transaction snapshot for its most recent commit, enabling a revision-labelled before/after observation pair without an unbounded snapshot history; the pair shares one pixel budget. Renderer-only collaboration state crosses a separate advisory IPC path: while an editor is attached it publishes document/tool/selection/zoom, visible viewport, and animation hints. Activation synchronously rebinds that advisory to the canonical active document and clears prior selection; late updates for any other document are ignored, and detach clears the advisory. The renderer changes canvas identity with the document ID, atomically clears shared selection/viewport/animation/reveal state on activation, and cancels old-document gesture commits and pending locks, so Bézier, pencil, selection, and other previews cannot cross tabs. Advisory state never mutates the canonical workspace or feeds back into workspace publication.

CPU-heavy and untrusted raster/provider work runs behind supervised Electron utility processes. Quantization, addressed import/conversion, document export, MCP observation compositing, generation comparison rendering, provider network/workflow execution, generated-preview acceptance normalization, accepted pixel-result quantization, and generic-image admission decode each use typed requests. For generic images, the main process first performs allocation-safe canonical base64, byte/hash, MIME/header, display-geometry, 8,192-side, and 16MP checks; only the worker-owned `validate-image` module imports the native decoder for that admission step. The production engine injects this validator into live asset admission, native open/save, and profile recovery; the import supervisor applies the same lane before returning a result, while CLI export owns a lazy supervisor. An unsafe payload rejects a live transaction without mutation; native open and CLI preserve metadata while omitting data with an explicit warning; save validates before main-process preview rendering. A utility import does not resolve until every embedded image passes the pure envelope checks and a supervised decode; a malformed result retires its producer, while a decoder crash returns no document. Recovery instead preserves the document plus asset metadata, omits only invalid data-bearing payloads, and exposes one aggregate warning on renderer bootstrap so recoverable unsaved work is not discarded silently. Metadata-only recovery entries retain their existing migration boundary. A worker handles one task at a time, rejects the active task on crash, and restarts fresh for queued work. Each independent supervisor retains at most 32 waiting requests; the next call gets explicit retryable backpressure, and queued cancellation frees capacity without changing FIFO order.

Pixel-mode APNG import uses a separate bounded container/frame decoder because it must recover editable animation frames rather than one native-decoder composite. Adam7 frames reuse the established per-frame inflate ceiling: the decoder computes the exact seven-pass row/filter byte count, unfilters each pass independently, and deinterlaces into the same packed sample rows used by noninterlaced color conversion. Byte-aligned and sub-byte samples therefore retain one conversion path. The animated path validates all chunk CRCs, a single monotonic `fcTL`/`fdAT` sequence, the declared frame count, and one empty terminal IEND; invalid interlace methods, illegal color-type/depth pairs, and structural or inflated-row contradictions fail before canonical construction. Static PNGs still return to the established general raster path. This adds no native decoder or format/schema state; current evidence is limited to generated RGBA and indexed fixtures.

Before APNG frame conversion, one color-metadata validator requires a legal, unique, pre-image-data `PLTE`/`tRNS` sequence and reconciles palette size, indexed bit depth, transparency payload width/range, and alpha-bearing color types. Indexed pixels must address an actual palette entry. Grayscale and truecolor `tRNS` keys are compared at their encoded precision—both bytes at depth 16—before the established high-byte display conversion. Invalid metadata rejects before canonical construction rather than supplying fallback pixels; this changes no resource ceiling, canonical palette model, export encoder, or source-retention contract.

The APNG parser models the two legal relationships between the PNG default image and the animation. An `fcTL` before the first `IDAT` makes that full-canvas PNG image the first animation frame; its compressed bytes remain one consecutive `IDAT` stream and cannot also arrive through `fdAT`. If the first `IDAT` arrives without a frame control, it is a separate fallback image: its exact inflated row/filter layout is validated under the same per-frame ceiling, but it is not composited into the animation, whose first control may describe a partial rectangle and whose bytes must use `fdAT`. This state is parser-local and adds no canonical default-image field, canvas offset, or export policy.

Every APNG chunk type is also validated as four ASCII letters with the PNG reserved third bit uppercase. After known PNG/APNG chunks are handled, an unknown type with an uppercase first letter rejects because its critical semantics can affect correct decoding; a lowercase-first ancillary type remains ignorable and its original bytes survive through source retention. This is an APNG-parser boundary after `acTL` detection, not a replacement policy for the general static-PNG decoder.

Editable GIF/APNG import plans palette assignment over composited full frames before writing indexed cels. At most 255 colors above the document alpha threshold may be visible in any frame because index zero remains transparent. Colors already present in the reference document palette retain their nonzero indexes; novel colors receive the lowest unused index in raster-discovery order, independently per frame. Every resulting palette has the same length, entry IDs, and order, with later colors represented through the canonical frame override. APNG planning consumes the decoder's existing full-frame buffers. GIF planning replays validated patches and disposal twice—once to plan and once to write—so it does not retain an additional array of full composited frames. An overflow in any frame discards the whole plan and routes every frame through the established document-palette quantizer with one warning; mixing exact and quantized frames was rejected because it would make fidelity mode implicit and frame-dependent. Exact source bytes remain embedded in either mode.

APNG export may bypass Canvas readback only when the animated sprite has exactly one ordinary pixel layer at full opacity and normal blend, the shape created by GIF/APNG import. That path resolves linked exposure, indexed chunks, and the frame palette directly into RGBA before established nearest-neighbor scaling and encoding, preserving stored partial-alpha channels that Canvas premultiplication can round. Any group, additional layer, opacity, or blend falls back to the established renderer. This adds no canonical/schema field, decoder ceiling, alpha-threshold change, general pixel compositor, GIF export promise, or broad animation compatibility claim.

GIF export reuses the same guarded indexed-frame resolver but accepts direct output only when every used nonzero palette entry is fully opaque. Eligible frames keep their canonical indexes through integer nearest-neighbor scaling; the encoder writes frame zero's RGB palette as the global color table and supplies later frame palettes as local tables. If any frame is ineligible, the complete animation follows the established Canvas-rendered RGBA quantizer, so one GIF never mixes direct and quantized fidelity modes. GIF cannot represent partial alpha, and this path does not preserve unused transparent RGB or container bytes. It changes no canonical state, tag sequence, delay, loop, dimension ceiling, or complex-composite renderer.

Static PNG export for an active sprite and sprite-sheet export also use the guarded single-layer resolver, but they retain its complete RGBA—including partial alpha—rather than imposing GIF eligibility. Integer presentation scale is applied to raw pixels; sheets are assembled into one already-bounded RGBA surface and encoded losslessly with the maintained encoder's palette rewrite disabled. The no-PLTE setting preserves eight-bit channels and avoids that encoder's undersized tiny-palette output. A complex sheet is rejected by the resolver before the raw sheet allocation and follows the established Canvas compositor. This does not change JPEG/WebP/PDF, illustration or tilemap rendering, sprite-sheet geometry/metadata, canonical state, or PNG container/profile identity.

Quantization enforces its source-byte boundary before base64 amplification and validates child changes against the originating width×height and palette. Every other terminal result is governed by a main-owned post-IPC resource policy before caller, file, job, MCP, or canonical use. Export requires the exact request-derived primary MIME/extension and companion shape, canonical base64, safe leaf names, no duplicate Tiled names, at most 4,097 total members, and at most 512 MiB of aggregate decoded bytes before decode; an unexpected companion therefore cannot create an adjacent output file. Import accepts 1–256 documents, meters their JSON representation without allocating a second whole serialization against 512 MiB / 16,777,216 nodes / 128 levels, then applies the established migration/schema gate. Report and warning arrays share a 4,096-entry, 64-KiB-per-string, 1-MiB-serialized contract. Observation retains its exact request geometry, 4,194,304-pixel and 65,535-per-side output limits, static-PNG structure/full-decode, and 4 MiB PNG ceiling inside a generic serialized-result allowance derived from that PNG's maximum base64 plus 64 KiB. The distinct `observation_dimensions_too_large` result represents the side limit; `observation_too_large` remains the aggregate-pixel result. Generation retains request-derived count/seed and exact PNG/JPEG/WebP image contracts while provider metadata must be JSON-safe within 64 KiB / 4,096 nodes / 32 levels. Canonical provider/model/prompt provenance still comes from the approved main-owned request, never metadata.

Generation progress remains advisory: only the active request's finite 0–1 update with a message of at most 4 KiB is relayed; malformed, oversized, or cross-lane telemetry is ignored without aborting a potentially paid task. Terminal error codes/messages are bounded to 256 bytes / 16 KiB; the honest worker truncates oversized errors without splitting Unicode, while a malformed child envelope fails closed. Any invalid terminal result retires that worker and queued work restarts fresh. The exact meters deliberately avoid `JSON.stringify` of an entire untrusted result, but they run only after Electron has delivered the structured-cloned message and therefore do not establish a pre-deserialization or process-RSS ceiling.

At explicit human acceptance, a valid preview above the 1.5 MB inline/quantizer ceiling is normalized in the raster lane without resizing: lossless PNG re-encoding is tried first, then the first fitting quality from one fixed descending alpha-preserving WebP ladder. The accepted derivative must pass the exact inline-asset contract before quantization or commit; source and accepted hashes/bytes/codecs are recorded while the original provider output stays unchanged in the private job. If same-geometry output cannot meet the established byte or geometry contract, the result stays preview-only with guidance and no canonical mutation. Raster cancellation/timeouts replace the worker immediately; generation cancellation first signals its AbortController and allows bounded provider cleanup—such as ComfyUI queue removal/interrupt—before force replacement. Generation uses a separate lane so a long provider request cannot block drawing observation/export. The utility bundle is a required package artifact; exact Windows crash/cancel, queue/input-pressure, quantization-result, observation-codec, generated-preview acceptance-normalization, fixed sprite-sheet PNG+JSON export-result, import-result, and provider-free general-generation fixtures pass under their recorded narrow evidence. The new aggregate resource policy remains headless source evidence; exact RSS, broader platforms, real-provider pressure, and packaged/native acceptance remain release gaps.

Generation requests are capability-checked before approval and again before dispatch. They never silently change providers or automatically retry an ambiguous potentially paid POST. OpenAI outpaint is a real edit request: AIDraw pads the source into the requested output canvas and supplies a same-size alpha mask that exposes only the expanded region.

Interchange is explicitly hybrid rather than pretending at lossless foreign serialization. Standalone JPEG import parses a bounded EXIF IFD0 orientation in either TIFF byte order, verifies the decoder-applied display geometry, retains the original source bytes, and reports non-default orientation; it does not infer sprite-sheet/Tiled coordinate conventions or promise metadata-preserving JPEG export. SVG maps supported groups, transforms, styles, gradients, clips, blur, images, ranged text, and primitives into the native model. PSD retains supported group and text structure beside visible raster fallbacks and a composite. Its pinned adapter defines layer opacity in normalized 0–1 units: canonical illustration group/layer/companion and pixel-layer exports pass that value directly, and decoded illustration layers enter the model without another 255 divisor; the PSD byte remains the format's precision boundary. No legacy 0–255 heuristic is accepted. AIDraw's binary lock exports through the adapter's documented PSD lock-all representation on supported illustration groups/layers, text companions, and pixel layers. Illustration import maps only PSD lock-all to canonical locked state; individual transparency/composite/position/artboard locks remain unlocked and generate an explicit loss report rather than being widened into AIDraw's broader binary lock. The pinned decoder's presence of a `children` array is likewise folder authority, including `children: []`; import does not infer group kind from a name or require content, and pixel flattening emits no sprite for an empty group. Its AIDraw-generated ` · editable text` child is a narrow private companion contract: export stores the object name in the suffix prefix, opacity/blend/lock on the PSD surrogate layer, style runs, line leading, the text box, and the complete affine matrix with a first-run baseline offset; import removes that offset, decomposes a matrix-equivalent canonical transform, and trusts the metadata only when the exact suffix, canonical-length name, and zero-origin bounded shape match. It moves the surrogate's name/composite/lock back to the canonical text object and leaves the synthetic wrapper unlocked at normal/1. The companion layer stays hidden while its object stays visible, avoiding duplicate default rendering but requiring only one layer toggle to reveal editable text. Unmarked PSD text keeps the established general adapter, and the raster fallback remains visual authority. PDF export keeps supported simple paths/shapes, standard-font text, and images native while transparently rasterizing unsupported effect groups; PDF import retains page appearance and extracted text but does not yet translate general content-stream operators. Every adapter records its fallbacks and warnings.

## Security boundary

BrowserWindow uses sandboxing, context isolation, no Node integration, no webviews, denied permissions/navigation, CSP, and hardened Electron fuses. Production renderer assets are served only from the restricted `aidraw://app` protocol, with `file://` extra privileges disabled. IPC validates the exact sender/main frame. Hosted keys and the MCP token use Electron `safeStorage`: DPAPI on Windows, Keychain on macOS, and a supported system secret store on Linux. AIDraw refuses Linux `basic_text`. Hosted-provider keys remain main-owned, are passed only in the typed request for the isolated provider worker, and are never returned to the renderer or MCP; the provider bridge exposes write/removal plus configured/stored/availability status only. Provider rotations are serialized and atomically replace an encrypted file requested with mode `0600` on POSIX, while explicit removal can delete ciphertext without decrypting it when the operating-system backend is unavailable. The separately scoped MCP connection-settings action may reveal its own token to the renderer. Native backend and packaged-interaction acceptance remain release gates.

MCP uses authenticated stateful Streamable HTTP on a persistent first-available port from 48200–48231. Initialization reservations and retained transports share one exact 32-session ceiling, so a concurrent 33rd initializer receives HTTP 429 instead of allocating another server/actor. Authenticated transport DELETE is the explicit capacity-release boundary: transport close idempotently retires presence, 128-bounded resource subscriptions, and session-scoped folder trust, while `session_manage leave` remains presence-only. Duplicate subscriptions do not consume another slot and unsubscribe frees one. The engine deliberately has no unestablished idle-eviction policy; shutdown closes every transport. Model mutations are safe to perform headlessly. Files are accessed only by explicit canonical paths; session/persistent folder trust can skip repeated non-overwriting prompts. Every overwrite and every agent generation still requires prior authority, and such jobs remain pending until an editor attaches rather than weakening the boundary in headless mode.

The commit boundary replaces client-proposed entity revisions, creator IDs, and timestamps with authenticated actor/commit values, recursively including sprite layers, frames, and cels. Optional model/reasoning/task metadata is validated and persisted as client-declared attribution, not platform attestation. Undo/redo operates on the resulting trusted inverse so exact restoration is preserved. Generic canvas transactions cannot add or remove verified generation provenance. Embedded-asset deletion is rejected while image objects, paint tiles, linked previews, or provenance still reference it; an explicit ordered cascade remains possible and exactly invertible. Job enumeration is owner-scoped and sanitized before crossing MCP so result payloads and human approval details do not leak between sessions.

Inline assets do not grant filesystem authority, but they are still untrusted input. Only canonical base64 raster PNG/APNG/JPEG/WebP/GIF payloads are accepted, with a 1.5 MB decoded limit, SHA-256/length/MIME checks, safe header dimensions, an 8192 px side/16 MP limit, and a real codec decode before commit. Agent claims of a generated source are normalized to ordinary embedded data; verified generation status comes only from the engine-owned provenance path.

Addressed imports are likewise untrusted after file approval. Root files have format-specific byte caps; raster/PSD/PDF headers and decoded surfaces, animation frames, sprite-sheet expansion, Tiled layers/chunks/objects/tiles, and compressed layer output have explicit budgets. SVG/TMX/TSX reject DTD/entity declarations. Metadata, external tilesets, and source images may follow only realpath-resolved relative references contained within the approved root folder, preventing `..` and junction/symlink escapes without granting file enumeration.

The product remains a local desktop engine/editor with concurrent localhost MCP sessions. Windows is the release-evidence baseline. macOS/Linux runtime abstractions, secure-storage policy, login behavior, Forge makers, and native CI jobs are implemented; Apple Silicon additionally has the exact-artifact independent Level 2 MCP + Computer Use PASS itemized in `MACOS_DEVELOPMENT.md`. Neither platform is promoted to a verified release target until hosted native, clean-machine/signing, and Level 3 release gates pass. Remote service tenancy, accounts/cloud sync/remote multiplayer, mobile, and web remain separate programs.

Targeted illustration observation has a deliberately conservative allocation adapter rather than a second rendering authority. One DOM-neutral predicate admits only visible integer-positioned, integer-sized solid rectangles with no stroke inside identity/default object groups and layers, plus empty paint layers without persisted tile payloads. The main renderer translates the established Canvas path onto a four-pixel-expanded regional backing and extracts the exact request with raw RGBA copy. Canvas curve/stroke coverage can change phase on a differently sized surface, while masks, paint, filters, opacity/blend isolation, and transformed groups can depend on off-region pixels; every such document therefore retains the established full-artboard render followed by raw crop. This preserves pixels and model/interchange semantics while allowing a tiny request on a simple maximum artboard to avoid a 64-megapixel allocation. No origin, spatial index, generic clipping, or save/export contract is inferred.

Transient sprite/tilemap overlay rendering reuses the canonical outward-rounded raster viewport but remains separate from artwork storage. One validated projection-aware filter conservatively tests orthogonal rectangles or isometric diamond bounding boxes. It derives an offset range for a horizontal compact run algebraically, so million-cell replay/fill records are not expanded or submitted to Canvas merely to be clipped; scale-aware raster padding protects selection stroke coverage. Point selections remain canonical arrays and are scanned once, retaining only visible candidates for the two marching-ant passes. Preview/replay order, colors, opacity, transforms, compact operations, selection state, and actor attribution are unchanged. This bounds drawing rather than inventing a spatial index or changing undo/playback semantics.
