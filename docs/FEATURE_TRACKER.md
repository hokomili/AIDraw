## Status rules

| Status | Meaning |
| --- | --- |
| ✅ Verified | The workflow is implemented and covered by an automated acceptance, contract, or regression test. |
| 🟢 Working | The workflow is usable in the current editor, but its acceptance coverage is incomplete. |
| 🟡 Partial | A useful subset works, but a material part of the promised workflow or fidelity is absent. |
| 🟠 Scaffolded | The model or interchange path exists, but human authoring is too thin to call the feature usable. |
| ⬜ Missing | No meaningful implementation exists yet. |
| ⏸ Deferred | Explicitly outside the selected v1 scope or retired by a superseding product decision. |

Priorities are `P0` release blocker, `P1` core v1 workflow, `P2` completeness/fidelity, and `P3` polish. These values express release significance, not a standalone execution queue: the numbered **Recommended critical path** is the binding work-selection order, a later-step P0 remains release-blocking without preempting an earlier numbered P1 product step, and unrelated same-tier work does not supersede the selected path. A feature may move to **Verified** only when its exit criteria have an automated test.
