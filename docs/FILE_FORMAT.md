# Native file format

An `.aidraw` file is a ZIP container. Paths are UTF-8 and schema migrations are application-owned.

| Entry | Purpose |
| --- | --- |
| `manifest.json` | Format/schema identity, document metadata, revision, asset count, saving app version |
| `document.json` | Illustration or pixel document model without machine-local `filePath` or inline asset bytes |
| `assets/<sha256>` | Deduplicated imported/generated/rendered bytes, including sparse illustration paint tiles |
| `activity.json` | Persistent attribution/activity summary |
| `trace/transactions.jsonl` | Complete append-only attributed transactions for inspection and replay |
| `checkpoints/index.json` | Ordered summaries for at most the newest 32 named checkpoints |
| `checkpoints/<id>.json` | One attributed checkpoint summary plus its captured editable document |
| `preview.png` | Rendered current-document preview |

`document.json` is canonical; `manifest.json` is an integrity summary, not a second source of document truth. Native readers require the manifest's supported schema, document identity, kind, name, revision, timestamps, and generic asset count to match the persisted document exactly. A malformed or contradictory pair is rejected. A matched schema-1 pair remains supported and migrates to the current schema. Inline asset bytes in `document.json` are ignored: data is hydrated only from its exact `assets/<sha256>` entry after declared length and SHA-256 match, then generic images must agree with their PNG/APNG/JPEG/WebP/GIF MIME, 8,192-side/16MP display geometry, and a real codec decode in the supervised raster utility. Missing, corrupt, or undecodable payloads retain editable metadata but omit data with an explicit warning; invalid metadata rejects the container. Writers refuse non-canonical or hash/length/MIME/header/geometry/decoder-contradictory supplied bytes before preview rendering, temporary creation, or atomic replacement; deliberately absent payloads remain recoverable metadata. Inline admission retains its 1.5 MB decoded-byte ceiling, while native, utility-import-result, and recovery-payload validation reuse the ZIP binary-entry ceiling of 128 MiB rather than defining a second storage limit. This does not broaden the supported codec set.

The canonical `document.json` activity sequence requires exact record envelopes with unique IDs, a schema-valid actor and status, a nonempty transaction ID/label/timestamp, a finite nonnegative safe operation count, and optional string details. Provenance records likewise use unique IDs and the strict provider/model/prompt/source/mask/timestamp contract used by live provenance operations; `conversion`, when present, remains an extensible object. Malformed or duplicate records reject before activity UI, agent accounting, or asset-reference consumers. Missing asset references remain recoverable rather than turning auxiliary absence into whole-document rejection. `activity.json` is a writer-produced mirror, not a competing source of truth. These structural checks do not authenticate self-authored attribution or prove a provider request.

Schema-2 illustration state reuses the same application-owned contracts as live operations. Artboard geometry, root layer order, all group/vector/paint layer fields and editable strokes, all six object variants, brush presets, guides, snap settings, and animation fields must be finite, bounded, and structurally exact. Root/member IDs must be unique, while every layer/object record key must equal the entity's own ID. Malformed canonical records reject the document rather than being silently dropped. This does not require every referenced layer, object, mask, or asset to be present and does not reject valid unreferenced records; those partial-recovery semantics remain distinct from malformed fields and contradictory record identity. Existing schema migration/default behavior for absent illustration preferences remains supported.

Each `trace/transactions.jsonl` record is one compact version-1 writer envelope containing exact document/revision/timestamp/outcome metadata and one canonical transaction for the same document. Trace transactions retain the editor's existing 2 MiB serialized ceiling. Native and local-store readers ignore malformed, cross-document, or oversized records before inspection/replay; native open emits one aggregate warning without rejecting otherwise recoverable artwork. Writers reject an invalid supplied trace before atomic replacement. Valid history is not truncated by this policy and native import appends accepted records to the durable store in one batch.

The reader considers only the newest 32 checkpoint summaries. Each selected summary and its named payload must independently match the exact seven-field metadata contract—safe ID, current document ID, nonblank name, canonical UTC timestamp, schema-valid actor, nonnegative safe source revision, and manual/automatic kind—and those values must agree exactly. The migrated checkpoint document must carry the same document ID and source revision. Duplicate selected IDs and malformed summaries are ignored with an entry warning; missing or corrupt payloads exclude only that checkpoint so the main document and valid siblings remain recoverable. The writer applies the same checks and rejects invalid, inconsistent, or duplicate supplied checkpoints before atomic replacement. Persisted names deliberately do not inherit the 80-character manual-entry limit because repeated restore-generated safety names can be longer.

Pixel records use a recovery-normalize-then-validate contract. Missing legacy frame/cel entity metadata, empty chunks, recoverable record-key aliases, absent reusable-library/link/conversion preferences, and unavailable referenced records retain their established normalization or partial-recovery behavior. Duplicate raw entity IDs reject before normalization can overwrite content. The normalized result must then satisfy exact palettes/libraries, sprite/frame/cel, tileset/tile/collision/Wang, tilemap/layer/object, link, and conversion schemas. New pixel-asset operations share those nested shapes but continue to require complete live frame/cel references.

Pixel indices and tile GIDs are packed in 32×32 chunks inside `document.json`; ZIP compression makes them compact while keeping migration logic deterministic. Every chunk origin is an aligned bounded integer, its record key is the corresponding `x/32,y/32` coordinate, and its canonical base64 must decode to exactly 1,024 indexed bytes or 4,096 GID bytes. Tileset tile, animation, collision, and Wang counts reuse the existing Tiled-import ceilings. After shape validation, every canonical sprite-cel byte and reusable-stamp index must be smaller than the current palette length; every frame palette override must have that length and the same entry IDs in order, though its colors may differ. Invalid palette references reject rather than being remapped to transparent or the renderer's missing-color diagnostic. Missing cross-asset/group/link targets retain their established recovery behavior. Linked project assets store a portable relative path, SHA-256, and embedded cached source. The editor can embed one link, extract an embedded cache to a user-approved relative file, relink to a replacement source, or **Pack Project** to mark every healthy cache embedded. Hash mismatches and missing caches fail closed rather than silently changing project content.

Weighted non-Wang variants use ordinary typed properties: `aidraw:variantGroup` on tile definitions and signed `aidraw:variantSeed` on maps. Tiled JSON/XML export preserves those AIDraw-namespaced values as custom properties; they are not a standard Tiled random-brush contract and no external editor is claimed to interpret them. The canonical painted result remains exact GIDs, so changing the seed affects only later AIDraw variant choices and never rewrites existing cells.

Writers create an exclusive temporary file, flush and close it, reopen and validate the archive and document migration, then atomically rename it over the destination. Detailed undo stacks are session-only; activity, provenance, and transaction traces persist. A separate per-user trace store continues recording while a document is dirty or the editor window is closed, and is merged when the native document is saved or opened.

## Profile recovery state

Crash recovery is profile-local and separate from the portable `.aidraw` container. New document journals are named `document-<sha256(documentId)>.jsonl`, so an imported opaque ID never becomes a path component and case-distinct IDs remain distinct on case-insensitive filesystems. A safe direct-child legacy `<documentId>.jsonl` remains readable and appendable until the next successful compaction writes the hashed form; only then is that legacy file removed. Compaction and the fixed `workspace.json` index use exclusive unique temporary siblings followed by atomic replacement.

A journal begins with exactly one `{ "type": "snapshot", "document": … }` record and then zero or more `{ "type": "transaction", "transaction": … }` records for the same document. Recovery migrates the snapshot and replays canonical transactions in order only until the first torn JSON line, malformed or expanded envelope, invalid/cross-document transaction, or apply conflict. The already applied contiguous prefix is returned; later records are not skipped to because a missing commit could invalidate their meaning. Native open queues the initial snapshot before an immediate edit can append. Direct invalid/non-JSON journal writes are rejected without changing the last good file.

Before a recovered data-bearing generic asset reaches canonical consumers, its metadata, canonical base64, declared length/SHA, supported MIME/header, display geometry, 8,192-side/16MP limits, and real supervised decode must agree. Invalid payload bytes are omitted while the recovered document state and remaining asset metadata are preserved. The workspace snapshot carries one aggregate recovery warning, shown once when an editor attaches, rather than silently hiding missing artwork or rejecting the entire unsaved document. This reconciliation does not validate metadata-only recovery entries, rewrite the source journal immediately, or claim arbitrary image repair.

`workspace.json` supplies tab order and active identity only when its version-1 object contains an exact `documentIds` array of unique nonempty strings and, when present, an `activeDocumentId` included in that array. A corrupt index cannot discard valid per-document recovery: journals still reopen in deterministic validated-filename order with no inferred active tab. This policy does not add a journal byte/count limit or claim filesystem flush, power-loss durability, packaged restart, or cross-platform acceptance beyond the tested source contract.
